## 확정 아이콘: 리듬

앱 이름은 **여백**이며, **리듬**은 심볼 이름입니다. 높이가 다른 두 사선과 위아래의 깊은 파임, 둥글게 마무리한 하나의 실루엣을 선택한 그대로 사용합니다. 원본 경로는 [brand.js](brand.js)에 있고, 확정 시안은 보관 폴더의 코드를 불러오지 않습니다.

## 1. 이번에 고정하는 디자인

첫 시안의 따뜻한 종이색, 명조 제목, 얇은 구분선, 올리브색을 유지합니다. 라이트·다크에서 구조·여백·동작의 위치는 같습니다. 야간 모드도 같은 앱으로 느껴지도록 먹색에 녹색 기운을 남기고, 주요 버튼은 밝은 올리브로 전환합니다.

- 큰 표지 이미지 대신 파일 이름과 읽던 위치를 먼저 보여줍니다.
- 폴더·최근 읽기·설정의 하단 탐색은 앱 화면에만 있습니다.
- 독서 화면 하단에는 검색·책갈피·TXT 설정·책 정보·이동을 제공합니다. 본문을 탭하면 헤더·푸터가 함께 숨겨지고, 다시 탭하면 나타납니다.
- 메뉴는 고딕, 앱 이름·주요 제목·기본 TXT 본문은 명조로 구분합니다.
- 밝게 반짝이는 장식·큰 그림자·배경 그라데이션을 사용하지 않습니다.
- TXT MVP에서 PDF·이미지의 미구현 메뉴는 표시하지 않습니다.

## 2. 모드와 설정의 소유권

| 설정 | 기본값 | 저장 범위 | 변경 시 동작 |
| --- | --- | --- | --- |
| 앱 테마 | 기기 설정 따르기 | 앱 공통 | 폴더·메뉴·설정·대화상자 색상이 변경됩니다. |
| 시작 폴더 | 처음 실행에서 선택 | 앱 공통 | 다음 새 실행의 시작 위치가 됩니다. |
| TXT 본문 색상 | 앱 테마 따르기 | TXT 전용 | 앱 테마를 참조하며 별도 설정값으로 저장합니다. |
| TXT 고정 색상 | 라이트·세피아·다크 중 선택 | TXT 전용 | 앱 테마가 바뀌어도 선택한 본문 색상은 유지됩니다. |
| 글꼴·크기·간격·여백 | 명조·18·1.85·24 | TXT 전용 | 현재 읽는 문장을 기준으로 재배치합니다. |
| 인코딩 | 파일을 검사한 결과 | 책별 | 현재 책만 다시 준비합니다. TXT 표시 옵션 초기화 대상이 아닙니다. |

`AppTheme = SYSTEM | LIGHT | DARK`, `TxtPaper = FOLLOW_APP | LIGHT | SEPIA | DARK`로 의미를 분리합니다. 앱 테마 변경 시 TXT의 저장값을 덮어쓰지 않습니다. `FOLLOW_APP`일 때만 표시 결과가 바뀝니다.

독서 중 상·하단 툴바와 시스템 바는 **실제 본문 배경**에 맞춥니다. 읽기 설정 시트·책갈피·검색 등은 앱 테마를 따릅니다. 본문을 다크로 고정하고 앱을 라이트로 써도 밝은 시스템 바가 본문 가장자리에 남지 않도록 합니다. 시트가 열려 있는 동안에는 시스템 영역도 시트의 앱 테마를 따릅니다.

## 3. 화면별 확정 구성

| 화면 | 구성 | 주요 동작 |
| --- | --- | --- |
| 폴더 서재 | 여백 제목, 이어 읽기 카드, 현재 경로, 하위 폴더, TXT 목록, 하단 탐색 | 파일 열기·상위 경로·새로고침·파일 정보 |
| 이어 읽기 확인 | 책 아이콘, 질문, 파일명·진행률, 두 동작 | `폴더 보기` / `이어서 읽기` |
| TXT 독서 | 상단 제목·뒤로·진행률 퍼센트·책갈피, 연속 본문, 하단 독서 메뉴 | 본문 탭으로 헤더·푸터 표시/숨김, 검색·책갈피·읽기 설정·책 정보·이동 |
| 앱 설정 | 시작 폴더, 앱 테마, TXT 설정 진입, 이어 읽기 동작 설명 | 폴더 변경·기기/라이트/다크 선택 |
| TXT 읽기 설정 | 본문 미리보기, 글꼴, 크기, 줄간격, 여백, 본문 색상, 초기화 | TXT 전용 설정만 변경 |
| 최근 읽기 | 최근 기록, 마지막 위치, 원본 경로, 기록 관리 | 이어 읽기·기록 삭제 확인 |

검색·책갈피·인코딩은 독서 메뉴에서 여는 보조 화면입니다. 검색에는 결과 수·강조 문장·결과 이동·원래 위치 복귀가 필요합니다. 책갈피에는 문장 미리보기·이동·삭제를 제공합니다. 인코딩은 책 정보의 `글자가 깨져 보이나요?`에서 열고, 적용 전 미리보기를 제공합니다.

진행률 퍼센트는 상단 헤더에 표시합니다. 하단 `이동`은 `읽기 위치 이동` 시트를 열며, 여기에서 0~100% 슬라이더로 위치를 고릅니다. 슬라이더 조절 중에는 본문을 이동하지 않고, `이 위치로 이동`을 누를 때 반영합니다. 취소·닫기는 기존 읽기 위치를 유지합니다. 하단에 항상 보이던 진행률 바와 `메뉴 숨김` 버튼, 숨긴 메뉴를 다시 여는 떠 있는 버튼은 제거했습니다.

본문의 짧은 탭만 메뉴 표시 상태를 바꿉니다. 스크롤·드래그·길게 누르기·텍스트 선택·도구 조작은 메뉴 토글로 처리하지 않습니다. 헤더·푸터를 숨길 때 본문 레이아웃과 스크롤 위치는 그대로 유지합니다. 브라우저에서는 본문에 키보드 초점을 둔 뒤 Enter로도 전환할 수 있습니다. Android의 TalkBack 동작은 별도로 구현·검증합니다.

독서 기록 삭제는 원본 파일을 삭제하지 않습니다. 위치와 책갈피를 지우기 전에 별도 확인창을 띄웁니다. 파일 관리·원본 삭제 메뉴는 이번 범위에 넣지 않습니다.

## 4. 시작과 복구 흐름

1. 처음 실행: 시작 폴더 선택 안내 → Android 시스템 폴더 선택기 → 선택한 폴더.
2. 일반 새 실행: 설정한 시작 폴더. 직전에 둘러보던 하위 폴더를 새 시작 위치로 바꾸지 않습니다.
3. 독서 중 종료 후 새 실행: 시작 폴더 위에 이어 읽기 확인. 확인 전에 파일 접근 가능 여부를 검사합니다.
4. `폴더 보기`: 확인을 닫고 시작 폴더를 유지합니다. 독서 기록은 남깁니다.
5. 독서 화면에서 명시적으로 뒤로: 폴더로 돌아가고 다음 실행 확인 후보를 해제합니다. 독서 기록은 남깁니다.
6. 빈 폴더: TXT가 없다는 안내와 시작 폴더 변경. 원본이 들어오면 새로고침으로 확인합니다.
7. 권한 상실: 폴더 재연결·재시도. 기존 위치와 책갈피를 삭제하지 않습니다.
8. 읽던 파일 없음: 이어 읽기를 강행하지 않고 파일 상태 안내 후 폴더로 이동합니다.

회전과 일시적인 백그라운드 복귀에 이어 읽기 확인을 반복하지 않습니다. 자세한 수명주기 규칙은 [시작·이어 읽기 설계](../../docs/startup-resume-flow.md)를 그대로 적용합니다.

본문 준비 중에는 취소 가능한 준비 화면, 준비 실패에는 재시도·인코딩 재선택·폴더 복귀를 제공합니다. 원본 변경, 빈 TXT, 미지원 형식, 연결 해제 확인, 검색 진행·취소·실패·이전/다음 결과는 이 시안의 공통 컴포넌트와 문구 규칙으로 구현하되, 이번 정적 PNG의 별도 화면으로 모두 제작한 것은 아닙니다. 제품 계획의 해당 기능 범위는 유지합니다.

## 6. 글자·간격·컴포넌트

| 항목 | 기준 |
| --- | --- |
| 앱 이름 | 명조 31, 보통 굵기 |
| 화면 제목 | 고딕 16, 중간 굵기 |

| 파일 제목 | 고딕 13, 확장자 포함, 긴 이름은 말줄임·책 정보에서 전체 확인 |

| TXT 본문 | 기본 명조 18, 줄간격 1.85, 좌우 24 |
| TXT 조절 범위 | 크기 14~32, 줄간격 1.3~2.1, 좌우 16~40 |
| 간격 단위 | 4·8·12·16·24·32 |
| 터치 영역 | 최소 48×48, 텍스트 버튼은 긴 문구·큰 글씨에 따라 높이 증가 |
| 모서리 | 카드·버튼 약 4, 대화상자 8, 하단 시트 16 |
| 구분선 | 1, 본문 진행률 2 |
| 독서 메뉴 | 본문 위 오버레이, 메뉴 표시 여부로 본문 레이아웃을 밀지 않음 |

웹 시안은 360 CSS px 안쪽 폭을 기준으로 만들었습니다. Android에서는 크기·여백을 dp, 글자를 sp로 옮깁니다. CSS px를 실제 기기의 물리 픽셀로 고정하지 않습니다. 휴대폰 테두리·시안 설명·모드 전환 막대는 검토용이며 앱에 포함하지 않습니다.

브라우저 미리보기는 OS에 있는 명조·고딕 폰트를 사용합니다. Android 앱은 Noto Serif CJK KR 명조와 SIL Open Font License 원문을 번들로 포함합니다. 실제 Android 글꼴 메트릭과 문단·행간·앵커 검사는 앱의 검증 기록을 따릅니다.

## 7. 시안에서 확인할 수 있는 것

`index.html`을 브라우저로 열면 서버·빌드·인터넷 없이 동작합니다. 상단 라이트·다크는 앱 테마를 변경하는 검토용 버튼입니다. 앱 설정의 기기 설정도 실제 브라우저의 선호 테마에 반응합니다. 각 휴대폰은 독립된 화면 상태이며, 환경 설정은 여섯 화면에 공유됩니다.

- 폴더 이동·예시 시작 폴더 변경·파일 정보·이어 읽기 선택.
- 앱 테마·본문 테마 분리, 폰트·크기·간격·여백·TXT 초기화.
- 예시 본문 스크롤, 상단 진행률, 본문 탭으로 메뉴 숨김·표시, 하단 이동 시트의 위치 선택·적용·취소.
- 예시 본문 실제 문자열 검색, 결과 이동, 책갈피 추가·이동·삭제.
- 책별 인코딩 선택 UI와 기록 삭제 확인.
- 처음 연결·빈 폴더·권한 상실·파일 없음 상태에서의 다음 동작.

환경 설정만 브라우저 저장소에 보존합니다. 독서 기록·책갈피는 시연 중 메모리 데이터이며 초기화하면 돌아옵니다. 폴더 선택은 예시이며 OS 선택기나 실제 파일에 접근하지 않습니다. 인코딩 미리보기는 합성 문장으로, 디코더가 실제로 실행되는 것은 아닙니다. 실제 파일의 길이·진행률·검색 규모·성능을 보여주는 결과도 아닙니다.

브라우저에서는 문단 기준 위치를 보조 복원합니다. Android의 UTF-16 문자 앵커, 대용량 TXT 처리, 프로세스 종료·복귀, SAF 권한 보존은 앱 구현에서 검증합니다. 시안의 독립 화면들을 실제 앱의 동시 화면이나 전체 생명주기로 해석하지 않습니다.

## 8. 구현 인수 조건

- 라이트·다크·기기 설정과 TXT의 네 색상 선택 조합을 검사합니다.
- TXT 초기화 후 앱 테마·시작 폴더·위치·책갈피·책별 인코딩이 유지됩니다.
- 시스템 글꼴 배율 1.0·1.5·2.0, 좁은 화면·가로 화면·분할 화면에서 조작이 잘리지 않습니다.
- TalkBack에서 모달 초점 이동·복귀, 버튼 이름, 선택 상태, 본문 탐색 순서를 확인합니다.
- 테마 전환과 메뉴 표시로 읽던 문장이 이동하지 않습니다.
- 기능·상태·수명주기는 [UI 기준](../../docs/ui-guidelines.md), [기능 분리](../../docs/feature-boundaries.md), [개발 계획](../../plan.md)을 따릅니다.

색상쌍·브라우저 화면 검증과 실제 Android 접근성·기기 성능 검증을 구분합니다. 검증 기록은 [verification.md](verification.md)에 남깁니다.
