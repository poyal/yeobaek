# 여백 UI와 상태 복원 기준

작성일: 2026-10-13. 본문 읽기 품질과 큰 글씨·화면 변화에 대응하기 위한 구현 기준입니다.

시각 기준은 사용자께서 선택하신 **종이의 여백**입니다. 이 문서와 현재 Android 테마·공통 컴포넌트를 기준으로 구현합니다. 앱 테마는 기기 설정·라이트·다크, TXT 본문은 앱 테마 따르기·라이트·세피아·다크를 별도로 저장합니다. 기본 본문은 앱 테마를 따르며, 명시적으로 고른 본문 색상은 앱 테마 변경으로 덮어쓰지 않습니다.

브랜드 아이콘은 **리듬(3차 04)**으로 확정했습니다. 원본과 색상·단색 리소스는 [브랜드 원본](../assets/brand/)를 따릅니다. 서재 제목과 설정의 브랜드 표식에 적용하며, 검색·파일·폴더·책갈피 등의 기능 아이콘은 각 동작의 의미를 유지합니다.

## 1. 공통 컴포넌트

서재·설정·대화상자의 글자가 있는 동작은 공통 버튼으로 제공합니다. 초기 이름은 `PrimaryAction`, `SecondaryAction`, `CompactAction`, `ActionGroup`으로 제안합니다.

| 역할 | 사용할 곳 | 공통으로 관리할 값 |
| --- | --- | --- |
| 주요 동작 | 시작 폴더 연결, 인코딩 적용 | 최소 높이·채운 배경·활성/비활성 색 |
| 일반 보조 동작 | 재시도, 기본값 복원 | 여백·테두리·글자 스타일 |
| 작은 보조 동작 | 검색 이전/다음, 대화상자 | 최소 터치 영역·줄바꿈·간격 |
| 동작 묶음 | 여러 인코딩/설정 보조 버튼 | 가로·세로 간격과 자동 줄바꿈 |

일반 버튼은 최소 48dp 터치 영역을 확보합니다. 글자 길이·시스템 fontScale에 따라 높이가 늘어날 수 있어야 합니다. 동작 이름을 고정 한 줄 말줄임으로 숨기지 않습니다. 여러 버튼은 좁은 화면에서 다음 줄로 이동하게 합니다.

화면별로 공통 버튼의 높이·글자 크기·안쪽 여백을 임의로 덮어쓰지 않습니다. 아이콘 버튼, 탐색 행, 선택 칩은 역할에 맞게 따로 유지합니다. 삭제는 명시적인 문구와 오류 색상을 사용합니다.

구현 후 공통 UI 규칙을 검사하는 작은 스크립트나 정적 규칙을 마련합니다. 정규식 검사를 사용한다면 주석·문자열을 제외하고 기반 버튼을 구현하는 공통 파일만 예외로 둡니다. 정적 통과와 실제 화면의 잘림 검사는 별개입니다.

## 2. 독서 화면의 독립성

본문은 하나의 최상위 Lazy 스크롤 컨테이너에서 표시합니다. 일반 입력 화면의 `Column.verticalScroll` 안에 TXT 목록을 넣지 않습니다.

문단마다 카드나 가변 외곽 여백을 두지 않습니다. 저장 블록·화면 블록이라는 내부 구현이 사용자에게 페이지 경계처럼 보여서는 안 됩니다.

앱의 UI 타이포그래피와 본문 읽기 스타일을 분리합니다. 본문을 작게 설정해도 설정 버튼과 검색창이 작아지지 않아야 합니다. 태블릿에서는 읽기 열의 최대 폭을 고려하되 폭이 바뀌면 문자 앵커로 복원합니다.

## 3. 메뉴와 피드백이 본문을 밀지 않게 하기

툴바와 짧은 알림은 본문 위의 오버레이로 표시합니다. 메뉴 표시 여부가 본문 측정 폭이나 저장된 진행률을 바꾸지 않아야 합니다.

독서 본문을 짧게 탭하면 헤더·푸터를 함께 숨기고, 다시 탭하면 표시합니다. 스크롤·드래그·길게 누르기·텍스트 선택은 메뉴 토글로 처리하지 않습니다. 진행률 퍼센트는 상단 헤더에 두고, 하단 `이동`에서 별도 진행률 슬라이더를 엽니다. 위치를 조절하는 동안 기존 읽기 위치를 유지하고 적용 동작에서만 이동합니다. 취소·닫기로는 위치를 바꾸지 않습니다.

오버레이는 안전 영역을 침범하지 않고 실제 컨트롤 영역에서만 터치를 받습니다. 닫힌 메뉴의 투명 레이어가 스크롤을 가로채지 않아야 합니다. TalkBack에서는 메뉴가 열렸을 때의 초점 이동과 닫혔을 때의 본문 복귀를 확인합니다.

뷰어 하단 메뉴는 `ReaderToolbar`를 공유합니다. **이동 → 책갈피**를 앞에 두고 **설정**을 마지막에 둡니다. 가운데에는 TXT의 검색·정보, PDF의 검색·색상 반전, 이미지의 색상 반전을 배치합니다. 공통 항목의 이름·아이콘·간격·최소 높이는 같으며 아이콘과 글자, 여백을 포함한 전체 셀을 누를 수 있습니다. 큰 글씨에서는 라벨을 두 줄까지 허용하고 모든 항목의 높이를 함께 늘립니다. 색상 반전은 아이콘과 접근성 상태로 켜짐/꺼짐을 구분합니다. 앱 바깥의 탐색 메뉴는 **홈 → 최근 읽기 → 설정**이며 홈에는 집 모양 아이콘을 사용합니다.

`책갈피를 저장했어요` 같은 알림은 접근성 설정에 맞는 표시 시간을 사용합니다. 사라지는 이전 알림은 semantics와 액션을 비활성화하여 오래된 실행취소가 다른 책에 작동하지 않도록 합니다. 확인이 필요한 오류는 자동으로 사라지는 알림에만 담지 않습니다.

## 4. 시스템 바·키보드·화면 크기

시스템 inset의 소유자를 정합니다. Scaffold padding을 이미 적용했다면 같은 inset을 중복 적용하지 않습니다. 검색 키보드가 뜨거나 닫힐 때 콘텐츠 높이와 앵커를 함께 확인합니다.

설정 패널·검색 결과가 큰 글씨와 가로 화면에서 세로 공간을 다 차지하면 배치를 바꾸거나 내부 스크롤을 제공하되, 사용자가 입력한 값과 초점은 유지합니다. 같은 상태를 가진 UI를 불필요하게 제거·재생성하지 않습니다.

검사할 상황은 세로/가로, 좁은 분할 창, 태블릿 폭, 시스템 fontScale 1.0/1.5/2.0, 밝게/어둡게/세피아, 키보드 표시/숨김입니다. 창 크기 변경 결과와 폴더블 실기기 결과를 구분합니다.

특정 OS의 우회 코드는 동일한 문제가 재현될 때만 추가하고 OS·재현 조건·이유·회귀 검사와 함께 기록합니다.

## 5. 읽기 설정 변경

설정 첫 화면에서 일반 설정과 TXT·EPUB·PDF·이미지 뷰어 설정을 바로 엽니다. 중간 뷰어 선택 화면은 두지 않습니다. 설정 첫 화면, 일반 설정, 각 뷰어 설정, 앱 정보·업데이트는 `SettingsPage`의 화면 여백·스크롤을 공유하며, 항목 묶음은 `SettingsCard`·`SettingsSection`으로 표시합니다. 종이색 화면 위에 밝기 차이가 있는 카드 배경과 얇은 테두리를 두고, 제목·아이콘·안쪽 간격·둥근 모서리를 통일합니다. 독서 기록 백업과 초기화 항목에도 같은 카드 규칙을 적용합니다.

EPUB 일반 본문은 원본 서식·글꼴·크기·색상·읽기 방식을 설정합니다. 원본 서식을 끄면 줄 간격·여백을 추가로 표시합니다. 고정 지면에서는 적용되지 않는 본문 옵션을 숨기고 바깥 배경만 제공합니다. 공통·폴더·책의 범위 규칙은 다른 형식과 같습니다.

앱 설정의 시작 폴더·UI 테마와 TXT·PDF·이미지/만화 설정은 별도 그룹입니다. 독서 중에는 현재 형식의 설정만 열고, 아직 구현하지 않은 형식의 설정은 노출하지 않습니다. 앱 UI 테마와 TXT 본문 색상도 독립적으로 저장합니다. PDF·이미지의 바깥 배경 변경은 페이지 내용의 색 변환을 뜻하지 않습니다. [기능·설정 분리](architecture.md)

각 그룹의 기본값 복원은 그 그룹만 초기화합니다. TXT 표시 옵션 초기화로 앱 설정·다른 뷰어 옵션·책별 인코딩·위치·책갈피가 바뀌지 않아야 합니다. 아래 재배치 절차는 TXT에 적용하고, PDF·이미지의 화면 맞춤·확대는 해당 형식의 좌표로 복원합니다.

설정은 현재 읽는 문장을 기준으로 바꿉니다. 절차는 앵커 캡처 → 최신 설정 확정 → 이전 작업 취소 → 주변 본문 재배치 → 앵커 복원입니다.

색상만 바뀌면 전체 본문을 다시 파싱하지 않습니다. 폰트·글자 크기·줄간격·여백·density·fontScale·실제 폭이 바뀌면 관련 레이아웃 캐시를 무효화합니다.

슬라이더의 모든 중간값을 디스크에 저장하거나 책 전체 레이아웃으로 만들지 않습니다. 마지막 설정이 화면과 저장소 모두에 남고, 복원 중의 임시 스크롤 값은 읽기 기록을 덮지 않게 합니다.

## 6. 접근성·대비

- 본문은 실제 텍스트 semantics를 제공합니다. 책 전체를 하나의 거대한 노드로 합치지 않습니다.
- 버튼에는 이름·활성 상태를, 책갈피에는 저장 상태를 제공합니다.
- 색만으로 선택·오류를 표현하지 않습니다.
- 텍스트와 배경의 대비는 기본 목표 4.5:1, 의미 있는 컨트롤 윤곽은 3:1로 검증합니다.
- 밝게·세피아·어둡게에서 본문·메뉴·검색 강조의 실제 색 조합을 검사합니다.
- 큰 글씨에서 터치 영역과 표시 영역이 겹치거나 잘리지 않는지 확인합니다.

위 수치는 제품의 검증 기준이며, 일부 색상쌍 검사를 통과했다고 앱 전체 접근성 검증을 완료한 것으로 표시하지 않습니다.

## 7. 사용자 문서와 화면

앱 구현 후 README는 `설치 → 시작 폴더 설정 → 폴더에서 열기 → 읽기 설정 → 이어 읽기 확인 → 검색·책갈피 → 재연결·기록 삭제`를 따라갈 수 있는 매뉴얼로 작성합니다. 최신 버전의 변경 내역이 사용법을 대체하지 않게 합니다.

스크린샷은 실제 앱과 합성 본문으로 만들고 해당 조작 설명 옆에 배치합니다. 디자인 시안을 실행 결과로 쓰지 않습니다. 개인 책·파일 경로·본문이 공개 이미지에 들어가지 않도록 합니다.

사용법, 버전별 변경, 실제 검증 기록, 개발 구조는 별도 문서로 관리합니다. 앱에 도움말 이미지를 포함한다면 필요한 파일만 묶고 문서의 원본과 동일한지 확인합니다. 앱 자산이나 캡처 코드의 변경은 단순 Markdown 변경과 구분합니다.


## 브랜드 원본과 버튼

확정 아이콘은 리듬입니다. `assets/brand/`에 밝게·어둡게·단색 SVG와 생성 원본을 보관합니다. `node assets/brand/export-assets.cjs`로 다시 생성합니다. 앱 런처·색상은 Android 리소스에서 관리합니다. 버튼은 `PaperButton`의 주요·보조·위험 스타일을 공유하며 초기화·캐시 정리·연결 해제는 빨간 테두리, 최종 삭제·해제는 빨간 채움을 사용합니다.
