# PDF·만화 및 추가 형식 확장 조사

조사일: 2026-10-13. TXT MVP 이후의 판단 자료입니다. 이 문서가 PDF·만화 기능을 이미 지원한다는 의미는 아닙니다.

앱 공통 기능과 형식별 옵션의 소유권은 [기능·설정 분리](feature-boundaries.md)를 따릅니다. PDF·이미지/만화는 각각의 설정 모델·화면·초기화 범위를 갖고 TXT 표시 옵션을 상속하지 않습니다.

## 1. 공통화할 것과 형식별로 둘 것

| 공통 계층 | 형식별 구현 |
| --- | --- |
| 시작 폴더·하위 탐색, 문서 접근·내용 버전, 책 ID | TXT 인코딩 / PDF 파서 / 압축파일 목록 |
| 최근 읽기, 책갈피 목록 | TXT 문자 / PDF 페이지·좌표 / 만화 이미지·좌표 |
| 메뉴 틀, 앱 UI 테마, 설정 진입점 | TXT 글꼴·본문 색상 / PDF 맞춤·간격·배경 / 이미지 보기 방식·넘김 방향·맞춤 |
| 취소·오류·진행 상태 | 텍스트 검색 / PDF 텍스트 추출 / 이미지에는 OCR 필요 |

공통 인터페이스는 열기·닫기·이동·현재 위치·가능한 기능 정도로 시작합니다. 모든 형식에 `pageCount`, `fontSize`, `search`가 존재하도록 강제하지 않습니다.

```text
Locator (schemaVersion 포함)
  Txt   = contentVersion + utf16Offset + layout 보조값
  Pdf   = sourceHash + pageIndex + 페이지 내 정규화 좌표
  Comic = sourceHash + entryId + 이미지 내 정규화 좌표
  Epub  = 해당 엔진의 publication/resource locator

ReaderCapabilities
  reflow, textSearch, textSelection, zoom, fixedPages, readingDirection
```

PDF·이미지의 원본 좌표를 화면 픽셀 좌표와 분리합니다. CropBox·회전·이미지 방향·확대 상태에 따른 변환은 해당 엔진이 책임지며, 세로 스크롤과 좌우 넘김은 같은 논리 위치를 공유합니다.

## 2. PDF 엔진 후보

| 후보 | 확인한 내용 | 여백에 대한 판단 |
| --- | --- | --- |
| AndroidX PDF | 조사 시 공식 릴리스 표는 `1.0.0-beta01`(2026-08-26)입니다. 2026-04-22 릴리스에서 읽기·렌더링을 API 28까지 확장했다고 명시합니다. 일부 Compose·편집·OCR API는 experimental입니다. [릴리스 노트](https://developer.android.com/jetpack/androidx/releases/pdf) | 기본 뷰어를 빠르게 통합할 우선 조사 후보입니다. 사용 artifact별 요구 조건과 커스터마이징 범위를 다시 확인합니다. |
| 플랫폼 PdfRenderer | 기본 생성자는 API 21에 추가되었고 seek 가능한 파일 디스크립터가 필요합니다. API 35에는 LoadParams 생성자가 있습니다. [API 문서](https://developer.android.com/reference/android/graphics/pdf/PdfRenderer) | UI 제어가 필요할 때 후보입니다. 페이지 스크롤·타일·캐시·기능 차이를 앱에서 책임집니다. |
| Readium Kotlin | EPUB 2/3과 PDF를 지원하고 형식별 기능 지원표를 제공합니다. [공식 저장소](https://github.com/readium/kotlin-toolkit) | EPUB까지 묶을 필요가 생길 때 비교합니다. TXT만을 위해 도입하지 않습니다. |
| 별도 PDFium 래퍼 | 이번 조사에서 특정 래퍼의 최신 유지 상태·전체 의존성을 확정하지 않았습니다. | 위 후보가 요구를 만족하지 못하면 별도 조사합니다. 이름이 같은 오래된 래퍼를 임의로 선택하지 않습니다. |

AndroidX PDF가 현재 beta라는 이유만으로 사용 불가로 판단하지 않습니다. 반대로 네이티브 공식 라이브러리라는 이유로 모든 지원 OS에서 모든 기능이 같다고 보지도 않습니다. TXT 완료 시점의 릴리스와 실제 문서로 재평가합니다.

### PDF 첫 단계

로컬 PDF 열기, 세로 페이지 스크롤, pinch 확대, 현재 페이지와 페이지 내 위치, 기본 책갈피를 구현합니다. 검색·선택·암호 문서는 엔진별 지원을 확인한 뒤 범위에 추가합니다. 스캔 PDF는 이미지여서 검색하려면 OCR이 필요할 수 있습니다.

PDF 옵션은 페이지/폭 맞춤·페이지 간격·페이지 바깥 배경부터 제공합니다. 글꼴·글자 크기·TXT 인코딩 옵션은 표시하지 않습니다. PDF 옵션 변경·초기화는 TXT·이미지 기본값을 유지합니다.

큰 페이지를 매번 전체 해상도로 래스터화하지 않도록 화면 크기 렌더와 확대 타일을 검토합니다. 페이지 핸들·파일 디스크립터·Bitmap은 화면 수명과 함께 정리합니다. 공급자가 seek 가능한 입력을 주는지 확인합니다. 스트림만 있으면 선택 파일의 임시 캐시로 입력을 준비하며, 이를 영구 원본 사본으로 간주하지 않습니다.

**도입 게이트:** 500페이지 문서, 이미지 위주 큰 파일, 암호·손상 문서, 확대 반복, 빠른 페이지 이동, 메모리 회수, 최소 OS, release 빌드를 검증한 뒤 엔진을 확정합니다.

## 3. 만화책 첫 지원 범위

1. JPEG·PNG·WebP 이미지와 이미지로 구성된 ZIP/CBZ를 우선합니다.
2. 파일명은 `1, 2, 10`처럼 자연 정렬하되 숫자 토큰 overflow를 피하고 대소문자·동일 숫자·하위 경로의 tie-break를 고정합니다.
3. 세로 연속 보기, 한 장 보기·확대·이어 읽기를 구현합니다. 좌→우·우→좌 넘김은 한 장 보기에 적용합니다.
4. 가로 두 장·표지 예외·자동 여백 자르기는 사용 피드백 이후 확장합니다.
5. RAR/CBR·7Z·중첩 압축·암호 압축은 첫 만화 버전에 넣지 않습니다.

이는 초기 범위를 작게 잡기 위한 제품 선택이며 CBZ 자체가 모든 이미지 codec·파일명 인코딩을 보장한다는 의미는 아닙니다.

이미지/만화 옵션은 보기 방식·한 장 보기의 넘김 방향·화면/폭 맞춤·이미지 간격·바깥 배경으로 구성합니다. PDF에 비슷한 맞춤 옵션이 있어도 값을 독립 저장합니다. 단일 이미지는 한 장짜리 자료로 취급하며 이미지 사이 이동·넘김 방향 메뉴는 표시하지 않습니다.

### 이미지와 압축 처리

전체 압축파일을 풀거나 모든 이미지를 Bitmap으로 보관하지 않습니다. 원본 접근·버전 확인 후 seek 가능한 입력이나 필요한 임시 캐시에서 엔트리 목록을 만들고 주변 이미지만 디코딩합니다. 압축 엔트리를 랜덤 접근 가능한 파일처럼 직접 seek할 수 있다고 가정하지 않습니다.

Bitmap 메모리는 압축파일 크기와 다릅니다. 예를 들어 ARGB_8888의 4,000×6,000 픽셀 한 장은 픽셀 버퍼만 약 91.6MiB입니다. 먼저 크기를 읽고 화면에 맞게 downsample하며, 세로로 긴 웹툰 이미지는 타일/영역 디코딩과 호환 codec을 검토합니다. [Android 큰 이미지 가이드](https://developer.android.com/topic/performance/graphics/load-bitmap)

추출이 필요한 경로에는 경로 이탈·절대경로·중복 이름·엔트리 개수·총 해제 크기·해제 비율·개별 이미지 픽셀 수 제한을 둡니다. 특정 OS가 ZIP 경로를 검사하더라도 지원 OS 전체에 동일한 방어가 있다고 가정하지 않습니다. [Android ZIP 경로 이탈 안내](https://developer.android.com/privacy-and-security/risks/zip-path-traversal)

**도입 게이트:** 1,000장 CBZ, 매우 긴 이미지, 손상 엔트리, Unicode 파일명·중복 이름, 이미지 폭 변경, 확대 중 이동, 복귀 시 같은 이미지·좌표 유지로 검증합니다.

## 4. EPUB와 선택하지 않은 확장

Readium은 EPUB 엔진 후보로 조사 가치가 있습니다. 공식 저장소에서 EPUB 2/3·PDF는 지원, CBZ는 부분 구현, CBR은 계획 없음으로 표시되고 라이선스는 BSD-3-Clause로 안내됩니다. 이는 조사 시점의 저장소 설명이며 선택한 릴리스와 전이 의존성은 도입 시 다시 확인합니다. [Readium 공식 저장소](https://github.com/readium/kotlin-toolkit)

현재 사용자가 명시한 우선순위는 TXT → PDF·만화입니다. EPUB가 구현 편의상 먼저 보인다는 이유로 순서를 바꾸지 않습니다. DRM·온라인 서점 연동·타사 앱의 구매 콘텐츠를 여는 기능도 현재 범위에 포함하지 않습니다.

## 5. 네이티브 의존성·배포

PDF·이미지·압축 엔진을 도입하면 ABI·네이티브 라이브러리·APK 크기·16KB 페이지 환경이 새 검증 대상이 될 수 있습니다. APK의 ZIP 정렬·ELF LOAD 세그먼트 정렬 검사와 실제 16KB 환경 실행을 별도로 기록합니다. 정적 검사 통과만으로 실제 실행 호환성을 판정하지 않습니다. [릴리즈 운영](release-workflow.md)

엔진 선정 시 유지 상태·릴리스·지원 OS·네이티브 바이너리·라이선스 고지·안정성·성능을 한 표에 기록합니다. TXT 프로젝트의 Gradle에 미래 엔진을 미리 추가하지 않습니다.
