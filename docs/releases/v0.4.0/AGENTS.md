- `localReadingSearchBookmarksSettingsAndProcessDeath`: 실제 SAF, 내부 링크·돌아오기, 선택·복사, 목차·240개 검색 결과와 복귀, 책갈피·책별 설정, 실제 PID 종료·교체와 진행률 복원, 메뉴를 숨긴 상태의 회전, 시스템 글자 배율 2.0, 설정 첫 화면의 EPUB 진입.

## 장시간·성능 검사 범위

TXT 30분 검사는 EPUB 화면 수명·레이아웃·준비 상태를 최종 보완하기 전 release 후보에서 수행했습니다. **최종 APK의 장시간 검사로 표기하지 않습니다.** 해당 APK manifest, 결과와 메모리, 원시 로그.

- 50MiB TXT, 1,800,409ms 동안 1,953회 양방향 스크롤, PID 2590 유지. 스크롤 정지 후 보이는 첫 블록이 의도한 방향으로 이동하는지 검사했습니다.
- 수집한 PSS 67,533~88,237KiB, 시작 69,989KiB·종료 67,533KiB. 최종 후보에서는 TXT 통합·release 독서 여정을 별도로 통과했습니다.
- 최종 EPUB의 180초 사전 반복 검사는 110회 통과했습니다. JSON, instrumentation.
- 이어서 최종 소스 debug의 EPUB 30분 검사도 1,139회 통과했습니다. 40장·6,000문단 합성 책에서 장 이동·6,000건 검색·설정 전환·다시 열기를 반복했습니다. PSS 표본 228개는 222,974~289,781KiB, 첫 표본 244,147KiB·마지막 257,643KiB이며 FD는 168~184개였습니다. JSON뿐 아니라 instrumentation `OK (1 test)`와 오류 부재를 확인했습니다. 이 검사는 release 최적화 빌드의 프레임 성능 측정이 아닙니다.

최종 release의 대용량 여정은 7개 입력 파일을 각각 열고 80% 위치로 이동한 뒤 101MiB 파일의 제한 안내를 확인했습니다. 1MiB 책의 다시 열기 기록은 정확히 100행입니다. 열기 시간 원시 표본. 이미 캐시된 파일도 포함하므로 첫 열기 성능 보장으로 사용하지 않습니다.

에뮬레이터의 시간·메모리는 회귀 조사 자료입니다. 실물 기기의 프레임 P50/P95/P99·스크롤 체감 성능이나 메모리 상한을 입증하지 않습니다.

## 업그레이드와 배포

직전 공개 0.3.0을 설치하고 TXT·PDF·이미지 위치·책갈피·설정·시작 폴더를 준비한 뒤 앱을 삭제하지 않고 최종 APK로 덮어 설치했습니다. DB user_version만 4→5로 이전하고 기존 8개 테이블의 값·설정 파일·영속 SAF 권한·외부 TXT 원본이 유지됨을 비교했습니다. 실제 UI에서 이어 읽기, 50% 이후 위치·책갈피·글자 크기 19·다크 테마도 확인했습니다. 이전 DB, 이후 DB, 요약.

최종 판정은 PASS입니다. 2026-10-17 04:36 KST에 [v0.4.0](https://github.com/poyal/yeobaek/releases/tag/v0.4.0)을 최신 정식 릴리즈로 공개했습니다. 태그는 검증 소스 이후 문서·증거만 추가한 [`262295d`](https://github.com/poyal/yeobaek/commit/262295d291a7b2fe05afe918178fc8c741683416)를 가리킵니다. 검증한 APK와 한 줄 SHA-256 파일만 첨부했고 게시 단계에서 다시 빌드하지 않았습니다.

초안 재다운로드와 비로그인 공개 재다운로드 모두 파일명·크기·GitHub SHA-256 digest·체크섬·전체 바이트 대조를 통과했습니다. 실제 release 앱의 수동 업데이트 확인에서도 현재 버전과 최신 확인 버전이 모두 0.4.0으로 표시됐습니다. 검사 결과, 화면. 배포 후 확인 기록과 화면은 main에 문서 커밋으로 추가하며 릴리즈 태그는 유지합니다.
