## Windows 수정 빌드와 첫 공개 릴리즈

### 게시 후 확인

[GitHub v0.1.0](https://github.com/poyal/yeobaek/releases/tag/v0.1.0)을 2026-10-13 23:59:55 KST에 공개했습니다. 태그와 검증된 소스 커밋은 `5514eeaf932de1fc95fd5d966105c0c7ddce8794`입니다. 빌드 당시 base commit은 `517e431`이며, 그 위 미커밋 빌드 입력을 `sources.json`의 72개 파일 해시로 고정한 뒤 같은 소스를 위 커밋에 담았습니다. 게시 후 추가 커밋은 문서·확인 이미지·수령 기록만 변경합니다.

초안 파일과 공개 URL의 APK·체크섬을 각각 재다운로드해 고정된 로컬 파일과 바이트·SHA-256이 같음을 확인했습니다. 인증 없는 최신 릴리즈 API의 파일명·크기·digest도 일치합니다. 공개 파일 확인 기록을 보존합니다.

공개 APK를 에뮬레이터에 덮어 설치했고, 실제 앱의 업데이트 확인에서 최신 버전 0.1.0 표시를 확인했습니다. 샘플 폴더 연결을 유지한 채 비가 그친 오후 본문을 열어 두었습니다.

아래의 기존 arm64 기록은 이전 로컬 APK의 이력입니다. 이번 Windows 빌드는 별도 서명과 실행 증거를 사용합니다. 공개 파일 안내는 v0.1.0 릴리즈 문서에 있습니다.

- Android 16/API 36 AOSP x86_64, 전용 AVD `yeobaek-api36` / `emulator-5580`, 720×1600, density 320, host GPU, RAM 3GiB. 샘플은 합성 TXT 1,021개입니다.
- APK: `com.poyal.yeobaek`, `0.1.0` / code `1`, minSdk 30 / targetSdk 36, R8 및 리소스 축소, 23,288,048바이트.
- APK SHA-256: `928c297e99b6fb52ef9177bfb87198df13b9db0ab97bc19f6b98f8c25319c311`.
- 인증서 SHA-256: `5ad108f18a7477f91a281b4feb26301a14247e59440607c5f7710582ac92fd48`.
- 전달 파일: `.tools/releases/0.1.0-windows/yeobaek-0.1.0.apk`와 `.sha256`. 서명 검사, 패키지 정보, 16KiB zip 정렬 검사를 보존합니다. 정렬 검사는 16KiB 메모리 페이지 실기기 검사를 대신하지 않습니다.
- 빌드 입력과 검증 소스 해시, APK·내장 자산 명세, 현재 화면 갤러리.

이 checkout에는 이전 로컬 APK의 서명 키가 없었으며 GitHub에는 공개 릴리즈·초안·태그가 없었습니다. 이번에 만든 여백 전용 키를 첫 공개 버전부터 보존합니다. 이전 로컬 APK와는 인증서가 다르므로 그 설치의 덮어 업데이트 가능 여부를 이번 검사로 보장하지 않습니다. 키와 비밀번호는 `.tools/signing/yeobaek.jks`, `signing.properties`에만 두고 Git·공개 파일에서 제외합니다.

### 확인하고 수정한 내용

기존 Markdown 29개와 확정·보관 디자인 설명, 구현 코드, 검사·빌드 스크립트를 검토했습니다. 문서의 오래된 도구 버전·폰트·기본 옵션·시작 흐름 설명을 실제 코드에 맞추고 Windows 빌드·서명·에뮬레이터 실행 방법을 추가했습니다.

- 불완전한 캐시에서 `bytes` 메타데이터가 빠지면 NPE가 나던 경로를 정상 재생성 경로로 고쳤습니다. 필수 메타데이터 9개를 각각 제거하는 회귀 검사가 있습니다.
- 검색 결과의 선택 번호와 표시 목록의 시작 번호를 분리했습니다. 이전/다음으로 100개 경계를 넘고 목록 행을 눌러도 정확한 본문 위치로 이동합니다. 기존 코드에서 실패한 두 경계 검사를 통과합니다.
- 앱 복귀 시 폴더를 다시 조회하며, 취소·새 책·위치 이동 시 이전 비동기 결과를 무효화합니다. 저장 오류 안내와 위치 저장 재시도를 보강했습니다.
- 앱 정보·문의 및 업데이트를 페리로그에서 검토한 구조에 맞춰 추가했습니다. GitHub 정식 릴리즈 확인, APK 크기·해시·앱 ID·버전·서명 검사, Android 설치 화면, 설치 취소 후 Download 파일 보존을 포함합니다. 여백 릴리즈 파일명과 단일 APK 체크섬 형식을 별도로 정의했습니다.
- AOSP/Google DocumentsUI 선택기를 모두 검사하고, Windows UTF-8 보고서와 키보드 조건을 보정했습니다. 폴더 복귀 후 새 파일을 발견하는 회귀 시나리오도 추가했습니다.

### 현재 검사 기록

단위 검사 26개(TXT 9, 검색 경계 2, 업데이트 상태·검증 15)가 통과했습니다. TXT XML, 검색 XML, 업데이트 XML, Lint 오류 0 / 경고 23을 보존합니다. 경고는 도구·라이브러리 새 버전 안내와 기존 API/KTX 권고이며 숨기지 않았습니다.

검사별 최종 실행 결과는 아래에 기록합니다. 기본/큰 글씨의 앱 정보·업데이트, 본문·검색·시트·키보드·가로 화면을 실제 PNG와 UI 계층으로 확인했습니다. 큰 글씨에서 긴 문구가 줄바꿈하고 필요한 항목까지 스크롤할 수 있으며 주요 버튼이 겹치지 않습니다.

첫 Windows 부하 실행(`20261013-234127`)은 instrumentation이 통과했지만 긴 문단의 이동 캡처가 아직 로딩 중이고 목표 진행률에 이르지 않았습니다. 이 실행은 최종 부하 증거에서 제외했습니다. 실제 진행률 75~90%와 배치 완료를 함께 기다리도록 검사를 보강하고, 화면 수집기도 로딩 표시나 잘못된 진행률의 캡처를 거절하게 했습니다. 위 표와 갤러리는 보강 후 재검사 결과를 사용합니다.

에뮬레이터에서 새 APK의 기능을 확인하는 범위입니다. 기존 arm64 API 30 결과, 30분 연속 읽기·100회 재열기·Macrobenchmark는 아래의 과거 APK 증거이며 이번 빌드에서 재실행한 것처럼 계산하지 않습니다. 실물 60/120Hz 성능·발열·배터리·TalkBack 인수는 미실행입니다. 과거 프레임 목표 미달을 해결했다고 주장하지 않습니다.

개발 중 캐시·검색의 회귀 실패, 복구 검사의 셸/키보드 조건 실패, 로컬 업데이트 서버의 debug HTTP 허용 누락, 해당 XML의 Lint 필수 속성 누락을 재현한 뒤 수정했습니다. 실패 로그는 `.tools/verification/`의 별도 실행에 남겨 두었고 현재 결과에는 수정 후 통과한 실행만 포함합니다. 최종 복구 검사 4개는 통과했지만 최초 ADB 캡처 복사가 실패해, 기기에 남은 동일 실행의 캡처 폴더를 다시 가져온 뒤 13개 필수 화면을 확인했습니다. 수집 재시도 기록도 남겼습니다.
