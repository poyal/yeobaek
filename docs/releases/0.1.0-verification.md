# 여백 0.1.0 — 구현 및 검증 기록

작성일: 2026-10-13. 공개 파일 확인 추가: 2026-10-14. 아래 Windows 빌드를 첫 GitHub 릴리즈로 공개했습니다. 이전 개인 검증 APK의 이력도 보존합니다. 실물 기기의 성능·TalkBack 인수와 스토어 공개는 아직 수행하지 않았습니다.

### 게시 후 확인

[GitHub v0.1.0](https://github.com/poyal/yeobaek/releases/tag/v0.1.0)을 2026-10-13 23:59:55 KST에 공개했습니다. 태그와 검증된 소스 커밋은 `5514eeaf932de1fc95fd5d966105c0c7ddce8794`입니다. 빌드 당시 base commit은 `517e431`이며, 그 위 미커밋 빌드 입력을 `sources.json`의 72개 파일 해시로 고정한 뒤 같은 소스를 위 커밋에 담았습니다. 게시 후 추가 커밋은 문서·확인 이미지·수령 기록만 변경합니다.

초안 파일과 공개 URL의 APK·체크섬을 각각 재다운로드해 고정된 로컬 파일과 바이트·SHA-256이 같음을 확인했습니다. 인증 없는 최신 릴리즈 API의 파일명·크기·digest도 일치합니다. [공개 파일 확인 기록](0.1.0-windows-evidence/publication.json)을 보존합니다.

공개 APK를 에뮬레이터에 덮어 설치했고, 실제 앱의 업데이트 확인에서 [최신 버전 0.1.0 표시](0.1.0-windows-evidence/public-update.png)를 확인했습니다. 샘플 폴더 연결을 유지한 채 [비가 그친 오후 본문](0.1.0-windows-evidence/sample-preview.png)을 열어 두었습니다.

### 확인하고 수정한 내용

기존 Markdown 29개와 확정·보관 디자인 설명, 구현 코드, 검사·빌드 스크립트를 검토했습니다. 문서의 오래된 도구 버전·폰트·기본 옵션·시작 흐름 설명을 실제 코드에 맞추고 Windows 빌드·서명·에뮬레이터 실행 방법을 추가했습니다.

- 불완전한 캐시에서 `bytes` 메타데이터가 빠지면 NPE가 나던 경로를 정상 재생성 경로로 고쳤습니다. 필수 메타데이터 9개를 각각 제거하는 회귀 검사가 있습니다.
- 검색 결과의 선택 번호와 표시 목록의 시작 번호를 분리했습니다. 이전/다음으로 100개 경계를 넘고 목록 행을 눌러도 정확한 본문 위치로 이동합니다. 기존 코드에서 실패한 두 경계 검사를 통과합니다.
- 앱 복귀 시 폴더를 다시 조회하며, 취소·새 책·위치 이동 시 이전 비동기 결과를 무효화합니다. 저장 오류 안내와 위치 저장 재시도를 보강했습니다.
- 앱 정보·문의 및 업데이트를 페리로그에서 검토한 구조에 맞춰 추가했습니다. GitHub 정식 릴리즈 확인, APK 크기·해시·앱 ID·버전·서명 검사, Android 설치 화면, 설치 취소 후 Download 파일 보존을 포함합니다. 여백 릴리즈 파일명과 단일 APK 체크섬 형식을 별도로 정의했습니다.
- AOSP/Google DocumentsUI 선택기를 모두 검사하고, Windows UTF-8 보고서와 키보드 조건을 보정했습니다. 폴더 복귀 후 새 파일을 발견하는 회귀 시나리오도 추가했습니다.

첫 Windows 부하 실행(`20261013-234127`)은 instrumentation이 통과했지만 긴 문단의 이동 캡처가 아직 로딩 중이고 목표 진행률에 이르지 않았습니다. 이 실행은 최종 부하 증거에서 제외했습니다. 실제 진행률 75~90%와 배치 완료를 함께 기다리도록 검사를 보강하고, 화면 수집기도 로딩 표시나 잘못된 진행률의 캡처를 거절하게 했습니다. 위 표와 갤러리는 보강 후 재검사 결과를 사용합니다.

에뮬레이터에서 새 APK의 기능을 확인하는 범위입니다. 기존 arm64 API 30 결과, 30분 연속 읽기·100회 재열기·Macrobenchmark는 아래의 과거 APK 증거이며 이번 빌드에서 재실행한 것처럼 계산하지 않습니다. 실물 60/120Hz 성능·발열·배터리·TalkBack 인수는 미실행입니다. 과거 프레임 목표 미달을 해결했다고 주장하지 않습니다.

개발 중 캐시·검색의 회귀 실패, 복구 검사의 셸/키보드 조건 실패, 로컬 업데이트 서버의 debug HTTP 허용 누락, 해당 XML의 Lint 필수 속성 누락을 재현한 뒤 수정했습니다. 실패 로그는 `.tools/verification/`의 별도 실행에 남겨 두었고 현재 결과에는 수정 후 통과한 실행만 포함합니다. 최종 복구 검사 4개는 통과했지만 최초 ADB 캡처 복사가 실패해, 기기에 남은 동일 실행의 캡처 폴더를 다시 가져온 뒤 13개 필수 화면을 확인했습니다. ## 검증 조건

전용 AVD `yeobaek-api30`(Android 11), `yeobaek-api36`와 `yeobaek-perf36`(Android 16), arm64, density 320 / 기본 fontScale 1.0을 사용했습니다. API 36과 기본 화면 검사는 720×1600입니다. API 30 재부팅 직후 복원·100회 재열기는 1080×2280에서 실행되었으며, 이후 화면 검사는 720×1600으로 다시 맞췄습니다. 각 실행 manifest의 실제 크기를 기준으로 해석합니다. 큰 글씨 검사는 2.0, 가로 화면 검사는 회전으로 수행했습니다. API 30은 3버튼 탐색, API 36은 제스처 탐색을 확인합니다.

연결 기기는 위 전용 에뮬레이터 세 대이며 실물 Android 기기는 연결되지 않았습니다.

모든 본문은 합성 자료입니다. 생성기와 해시 목록으로 재현하며 외부 소설·개인 TXT를 사용하지 않았습니다. 1/10/50MiB 일반 본문, 100MiB 스트레스, 101MiB 제한, 줄바꿈 없는 약 1MiB, 빈 줄 수십만 개, 결합 문자·이모지, UTF-16과 CP949, 손상/빈 TXT, 1,000개 파일 폴더를 포함합니다.

**에뮬레이터 수치의 용도는 기능·회귀·부하 진단입니다.** 같은 64GiB 호스트에서 전용 AVD를 병행했습니다. 본 측정은 SwiftShader 소프트웨어 GPU, 별도 비교는 호스트 GPU를 사용했습니다. 실물 60/120Hz의 프레임 목표, 발열·배터리·메모리 목표 통과로 일반화하지 않습니다. Macrobenchmark AVD는 가상 4코어·메모리 약 2.4GiB이고 CPU 고정 조건이 아니므로, 계획의 4GB급 실물 기준과도 다릅니다.

## 측정 해석

`OpenText`는 파일 열기 요청부터 디코딩·원본 해시 확인·화면 블록 준비 후 `readerReady`까지의 앱 트레이스입니다. UIAutomator의 `open_ready_ms`는 탭·idle 대기·본문 노드 확인까지 포함하므로 서로 같은 측정값으로 비교하지 않습니다. 최초 준비 표본은 파일별 1회이며 P95 목표 통과를 주장할 수 없습니다.

Macrobenchmark의 PASS는 지정한 반복과 트레이스 수집이 끝났다는 의미입니다. 프레임 목표 통과는 별도 수치로 판단하며, 이 에뮬레이터 실행에서 발생한 긴 프레임은 그대로 보고합니다. 실물 측정 전까지 “끊김 없음”이나 60/120Hz 성능 완료로 표시하지 않습니다. 프레임 표본의 P50/P95/P99는 반복 전체를 합친 선형 보간값입니다.
