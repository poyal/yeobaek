## 실제 프로세스 종료·복원

외부 사용자 여정에서 종료 전후 PID가 다른 기록 40건을 확인했습니다. 32건은 `am kill`, 4건은 `am force-stop`으로 기록됐습니다. EPUB 페이지 모드 4건은 `am kill` 실패 시 `force-stop`을 쓰는 기존 검사이며 최종 분기를 별도 저장하지 않아 두 방식 중 어느 것이 실행됐는지는 구분할 수 없습니다. 네 건 모두 기존 PID 종료와 새 PID의 위치 복원은 확인했습니다. Activity 재생성과 실제 OS 재부팅 결과는 이 수치에 합산하지 않습니다.

## 공개판 덮어 설치와 재시작

공개 v1.0.3 APK(SHA-256 `fde41d00f1ffab84f98e0cd86f7ee3ed66ef0ad5a6f6e7863f6caf5456c953f1`)에 합성 TXT·PDF·CBZ·EPUB의 위치와 책갈피를 만들고 v1.0.4를 삭제 없이 덮어 설치했습니다. 첫 실행 전 Room 스키마 5의 전체 테이블·DataStore 세 파일·영속 SAF 권한이 그대로임을 비교했습니다. UI에서도 네 형식의 위치·책갈피, 어두운 앱 테마, 책별 TXT 글씨 19, 시작 폴더·이어 읽기를 확인했습니다. 읽기와 재시작 후에도 Book ID·인코딩·본문 버전·책갈피 및 외부 파일 44개의 해시가 유지됐습니다.

| OS | 재시작 방식 | 이전 → 이후 boot ID |
| --- | --- | --- |
| Android 11 | `adb reboot` | `8de2f513-5eb2-4d49-81c1-107dbe42f130` → `d6001012-5c4d-47bc-9948-3c081632f614` |
| Android 16 | 앱 저장 확인·정지·게스트 `sync` 후 동일 AVD 종료·완전 부팅. 데이터 초기화·스냅샷 사용 없음 | `66f2e761-55ff-486b-8e03-b2ac44dfa381` → `87e1c418-535b-4544-b3d8-ff7ef400a258` |

Android 16의 일반 `adb reboot`는 한 번은 QEMU 종료, 다음에는 응답 정지로 완료되지 않았습니다. 따라서 이 OS에서 일반 재부팅 명령의 통과를 주장하지 않습니다. 게스트 동기화 없이 VM만 종료한 별도 시도에서는 최근 세션 revision 17이 16으로 돌아가 이어 읽기 후보가 사라졌습니다. 동기화 후 완전 재시작 검사는 통과했지만, 갑작스러운 전원 차단에 대한 최신 기록의 내구성은 검증 완료 범위에 포함하지 않습니다.

호스트 검사기의 Android 16 영속 권한 ABX 형식과 CBZ의 `IMAGE_ARCHIVE` 형식 판정을 보완한 뒤 처음부터 재검사했습니다. ABX는 읽기 전용 변환으로 확인하고 기기의 원본 권한 파일은 수정하지 않았습니다.

## 성능 비교 조건

Android 16 AVD 한 대만 실행하고 다른 기기 검사·빌드와 겹치지 않게 측정합니다. 기준은 작업 시작 당시 1.0.3 개발 후보로, 공개 v1.0.3 APK와 다르며 TXT 역방향 이동 수정은 이미 포함합니다. 따라서 이 비교에서 TXT 수정 전후의 성능 개선을 주장하지 않습니다.

기준 앱 소스는 `334b642e010e58a8e0e30c8f53bd8612159c27ee`에 최종 후보와 동일한 `TextLayoutEngine.kt`·`TextWindow.kt` 수정을 반영한 구성입니다. 저장한 시작 시점 패치와 최종 diff를 대조했습니다. 나머지 네 UI 수정과 버전 증가는 최종 후보에만 포함됩니다.

- 기준 benchmark APK SHA-256: `af3d5b396c80975246b9f1e373381c258b5ec65f4d2b205e38c6764e971c1600`.
- 최종 benchmark APK SHA-256: `9d5231f61518b9e9c20cf3382b89dfb55023373ff2c24fed689d6dbb2bf0bc7f`.
- 네 형식 검사 APK SHA-256: `363640aa8aacccd010bec67b142431be7e0309bfd4a68720eb342b764299cf9e`.
- TXT 검사 APK SHA-256: `a56838dc434edd93440807459dcf468204901e9f3a24e04b04f4439c03e3e458`. 각 비교 쌍의 기준·후보에는 같은 검사 APK를 사용합니다.

각 실행에서 앱을 새로 설치하고 OS·ABI·화면·글자 배율·그래픽·RAM·CPU·fixture·검사 APK·실행 인자를 대조합니다. 예비 검사의 1회·3회 표본은 정식 분포에 섞지 않습니다. 정식 지연은 항목별 30회, 스크롤은 항목별 10회 × 30초이며 캐시는 시나리오에 따라 먼저 준비합니다. UI 지연은 접근성 자동화와 화면 안정 확인 시간을 포함합니다. 이동·검색·목록·글꼴 변경은 ART `speed`, Macrobenchmark는 기존 Baseline Profile 필수 적용, TXT 재열기는 프로파일 없는 조건도 별도 측정합니다. 앱 내부 `OpenText` 구간과 UI 관측 시간을 구분합니다.

TXT 최초 정식 실행은 긴 문단의 반복 준비 단계에서 실패해 미완료로 처리했습니다. 별도 3회 재현의 실패 캡처에서 폴더 목록이 이전 스크롤 위치를 보존하고 있어 상단 새로고침 버튼이 화면 밖에 있음을 확인했습니다. 검사 코드가 목록을 위로 스크롤해 상단을 찾도록 보완하고 실패 화면 수집도 추가했습니다. 기준 앱의 폴더 진입 후에도 이전 목록 위치가 남는 두 번째 준비 실패를 캡처로 확인해 진입 뒤 상위 폴더 버튼도 스크롤해서 찾도록 보완했습니다. 최초 후보만의 예비 검사 대신 기준·후보 모두 6개 항목의 3회 반복 예비 검사를 통과했습니다. 앱 APK는 바꾸지 않았으며, 미완료 실행의 일부 측정값을 정식 기준으로 사용하지 않습니다. 성능 비교기는 두 실행 모두 같은 필수 지표를 누락해도 실패하도록 보강했고, Android 11에는 없는 프레임 기한 초과 지표는 API 31 이상에서만 요구합니다.

## 환경과 미검증 범위

전용 AOSP AVD `yeobaek-release-api30-040`(Android 11/API 30), `yeobaek-release-040`(Android 16/API 36)의 x86_64, 720×1600, density 320, 소프트웨어 그래픽, 4KiB 메모리 페이지를 사용합니다. 일반 검사는 fontScale 1.0이며 좁은 화면 검사만 별도 설정합니다. 합성 자료를 사용하고 사용자 기기·수동 검사 AVD는 초기화하지 않습니다.

기능 검사 도중 Windows 호스트의 QEMU 프로세스에서 약 100GiB의 메모리 사용이 기록되어 검사가 중단됐습니다. 이를 앱 PSS나 앱 OOM으로 집계하지 않습니다. 기존 Emulator 37.1.11/37.2.12는 보존하고 [OpenGL ES 자원 누수 수정](https://developer.android.com/studio/releases/emulator)이 포함된 37.2.13(build 16740729)을 별도 설치했습니다. 재개 환경은 2코어·SwiftShader·Vulkan 비활성화이며 RAM 실행 인자는 두 AVD 모두 2GiB입니다. Android 16은 에뮬레이터가 RAM을 2,560MiB로 자동 상향한 로그가 있어 실제 성능 환경의 `/proc/meminfo` 값 2,532,304KiB와 함께 기록합니다. 호스트 메모리 상한 감시를 추가했으며, 중단·시작 전 실패는 완료된 실행과 구분하고 해당 검사만 다시 실행했습니다.

Android 11 TXT 검사의 SAF 권한 창에서 접근성 노드가 교체되는 자동화 오류는 버튼을 다시 찾도록 보완했습니다. 초기 E2E APK SHA-256은 `ab192d8f077734c2d93fed9b8f7b314e8eea27909573fea6bbfa3f0ff30d9159`, 보완 APK는 `03ecf09b61948d332599e60c1d62d30a8ee07b00f872ab890e6512694f61f806`입니다. 재개 스크립트의 글자 배율 200% 잔류도 100%로 복원하고 실패 항목을 재검사했습니다. 앱 APK는 바꾸지 않았습니다.

실물 Android·ARM64·제조사별 동작, 16KiB 페이지 OS, TalkBack 실제 발화, 실물 SD카드 분리·저장 공간 고갈·클라우드 문서 공급자는 미검증입니다. 에뮬레이터 측정은 실물 기기의 FPS·발열·배터리 합격 판정을 대신하지 않습니다. 개발 중 버전 1.0.3 후보의 통과 결과는 이 버전의 최종 결과로 집계하지 않습니다.
