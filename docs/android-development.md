# 여백 Android 개발 기준

작성일: 2026-10-13. 기존 Android 프로젝트에서 확인한 구현·운영 경험 중 필요한 것을 **여백의 TXT 뷰어에 맞게 재작성한 기준**입니다. 다른 저장소의 문서를 열지 않아도 적용할 수 있도록 정리했습니다.

2026-10-17 현재 TXT·EPUB·PDF·이미지 읽기와 빌드·검사 도구가 구현되어 있습니다. 아래는 계속 적용할 개발 기준이며, 실제 구조·명령은 [구현 문서](implementation.md), 실행 여부는 [0.4.0 검증 기록](releases/0.4.0-verification.md)으로 확인합니다. 기준에 적혀 있다는 이유만으로 해당 검사를 통과한 것으로 간주하지 않습니다.

## 1. 지원 환경과 빌드

초기 최소 지원은 **Android 11(API 30)**입니다. 더 오래된 휴대폰·전자잉크 기기를 목표로 할 경우 실제 기기·메모리·텍스트 API부터 검증한 뒤 지원 범위를 넓힙니다.

`minSdk`는 설치 가능 범위이고, 기기 검증 완료 범위는 별도입니다. 지원표에는 공개 버전, 개발 후보, 실제 검사한 OS·기기·ABI를 나눠 기록합니다.

### 도구 조합의 출발점

현재 AGP 8.13.2 / Gradle 8.13 / Kotlin 2.2.21 / KSP 2.2.21-2.0.4 / JDK 17 / Compose BOM 2025.12.00을 사용합니다. `gradle/libs.versions.toml`과 Gradle Wrapper가 기준이며, 버전을 변경하면 SDK·의존성과 함께 빌드·실행 호환성을 다시 검증합니다.

- Gradle Wrapper와 배포 ZIP의 SHA-256을 버전 관리합니다.
- 의존성 저장소는 settings에서 중앙 관리하고 불필요한 저장소를 추가하지 않습니다.
- 라이브러리 버전은 version catalog 등 한곳에서 관리합니다.
- 직접 버전 고정과 전이 의존성 잠금은 구분합니다. 재현성을 확인할 때 실제 해석 결과도 남깁니다.
- debug는 독립 applicationId 접미사 `.debug`를 사용하여 개인 독서 기록과 검사 데이터를 분리합니다.
- release는 코드·리소스 최적화를 적용한 상태로도 검사합니다.
- SDK·JDK 경로는 개발 환경 설정으로 두고 개인 경로를 저장소에 고정하지 않습니다.

### 빌드 진입점

`scripts/build.sh`와 Windows용 `scripts/build.ps1`은 환경을 설정하고 지정한 Gradle task에 위임합니다. 검사 task를 지정해야 검사가 실행됩니다. 임의의 AVD 초기화나 배포는 기본 빌드 동작에 포함하지 않습니다.

개발 검사 흐름은 관련 단위 검사 → Lint → 필요한 빌드입니다. 공통 UI 규칙의 전용 정적 검사기는 아직 없으며 코드·화면 검토로 확인합니다. 작은 변경마다 전체 에뮬레이터·릴리스 검사를 반복하지 않습니다. 실제 Gradle task는 [구현 문서](implementation.md)에 있습니다.

## 2. 초기 구조와 객체 수명

| 경계 | 맡는 일 | 맡지 않는 일 |
| --- | --- | --- |
| Application의 작은 컨테이너 | Repository·설정 저장소 등 공유 객체 구성 | 모든 책 색인·미래 형식 엔진의 선행 초기화 |
| ViewModel | 현재 화면 상태, 사용자 이벤트, 작업 취소 | Activity·View 장기 보관, 본문 전체 복제 |
| Repository | 서재·위치·책갈피의 일관된 저장 | 화면 레이아웃·픽셀 좌표 계산 |
| 순수 TXT core | 디코딩·정규화·인덱스·검색 | Compose 상태·Context·Android View 의존 |
| 렌더러 | 현재 창의 줄 측정·스크롤·앵커 변환 | 폴더 연결·DB 마이그레이션 |

초기에는 생성자 주입과 수동 컨테이너로 구성합니다. I/O·시계·작업 dispatcher·저장소 경계는 테스트 대역을 넣을 수 있도록 둡니다. 클래스마다 의미 없는 인터페이스를 만드는 것은 피합니다.

서재 목록, 현재 책, 현재 책의 책갈피, 본문 창은 별도 관찰 상태로 둡니다. **읽기 위치 하나를 저장할 때 서재 전체와 TXT를 다시 불러오는 전역 Snapshot 구조를 사용하지 않습니다.** 화면이 보이지 않을 때의 Flow 구독과 작업 수명도 명확히 정합니다.

## 3. 상태 보존 규칙

| 상태 종류 | 저장 방법 | 예 |
| --- | --- | --- |
| 가벼운 화면 상태 | rememberSaveable / SavedStateHandle | 검색어, 열린 설정 패널, 서재 필터 |
| 장기 사용자 기록 | Room | 문자 앵커, 책갈피, 독서 세션 후보, 마지막 열람 시각 |
| 앱·형식별 기본값 | DataStore의 분리된 타입·키 영역 | AppPreferences의 시작 폴더·UI 테마, TxtPreferences의 본문 크기·줄간격·여백·색상 |
| 진행 중 작업 | ViewModel의 취소 가능한 Job과 요청 ID | 본문 로드, 검색, 설정 재배치 |
| 큰 본문·인덱스 | 내부 파일과 제한된 캐시 | 정규 UTF-8 텍스트, 블록 인덱스 |

SavedStateHandle에 전체 TXT·큰 JSON·Bitmap을 넣지 않습니다. 회전 후 UI 복원과 프로세스 종료 후 영속 위치 복원은 다른 검증 항목입니다.

독서 위치는 연속 스크롤 중에도 주기적으로 저장하고, 정지 후 마지막 위치를 저장합니다. debounce만 사용해 계속 읽는 동안 저장이 미뤄지지 않게 합니다. 책 전환 시 최종 저장을 요청하되 이전 요청이 새 위치를 덮지 못하도록 세션과 순번을 검사합니다.

화면 경로는 `Reader(bookId)`처럼 인자가 명확한 구조로 관리합니다. URI·전체 본문·Locator JSON을 긴 route 문자열에 끼워 넣지 않습니다. 서로 다른 책의 화면 상태를 같은 key로 공유하지 않습니다.

앱의 새 진입은 저장한 시작 폴더에서 시작합니다. 독서 중 종료 후보가 있으면 이어 읽기를 묻고, Activity 재생성·일시적인 앱 전환은 별도로 처리합니다. 종료 콜백에만 의존하지 않고 뷰어 진입에서 세션 후보를 저장합니다. [시작·이어 읽기 흐름](startup-resume-flow.md)

## 4. 비동기 작업과 중복 실행

본문 준비·검색·설정 재배치마다 아래 정체성을 갖습니다.

```text
작업 대상 = bookId + contentVersion + requestId
레이아웃 대상 = 작업 대상 + layoutGeneration
위치 저장 대상 = bookId + contentVersion + sessionId + sequence
```

UI 반영과 저장 직전에 정체성이 현재 대상과 같은지 확인합니다. 오래된 A책 로드가 B책 화면에 반영되거나, 18→22→20sp 변경 중 22sp 결과가 마지막에 표시되어서는 안 됩니다.

연속 탭으로 중복 저장할 수 있는 동작은 비동기 작업을 띄우기 전에 실행 여부를 확정합니다. 다만 앱 전체를 하나의 busy 값으로 잠그지 않습니다. 폴더 조회·본문 준비·검색·설정은 각각 자신의 상태와 취소 범위를 갖고 스크롤 입력을 막지 않습니다.

`CancellationException`은 취소로 전파하고, 일시적인 I/O 실패·권한 상실·입력 손상을 다른 상태로 표현합니다. 읽기 화면을 닫을 때 검색·프리페치를 취소하고 파일 핸들을 닫습니다.

## 5. 데이터 보존과 버전

Room 스키마를 export하고 이전 버전 파일을 보관합니다. 사용자 데이터가 있는 정식 버전부터는 파괴적 DB 초기화를 기본 복구 수단으로 쓰지 않습니다.

다음 버전은 서로 독립적으로 관리합니다.

1. Room 스키마 버전.
2. Locator 직렬화 버전.
3. TXT 정규화 알고리즘 버전.
4. 블록 인덱스 형식 버전.

DB를 이전할 수 있어도 옛 인덱스나 문자 오프셋의 의미가 달라질 수 있습니다. 인덱스는 재생성하고 기록은 가능한 범위에서 이전하는 절차를 각각 둡니다.

책과 관련 기록을 함께 변경하는 작업은 트랜잭션으로 처리합니다. 파일 확정과 DB 트랜잭션은 하나로 묶이지 않으므로 중간 종료 시 복구할 등록 상태가 필요합니다. 같은 요청의 재시도는 책·책갈피를 중복 생성하지 않아야 합니다.

설정 업데이트는 바뀐 필드를 현재 저장값에 반영합니다. 앱·TXT·EPUB·PDF·이미지 설정의 모델·갱신·초기화 범위를 분리하고, 오래 열린 설정창의 전체 객체가 다른 설정을 덮지 않도록 합니다. 인코딩은 책별 데이터로 보존합니다. 수동 백업 복원에서는 Room과 DataStore 사이의 복원 순서와 실패 복구도 확인합니다. [기능·설정 분리](feature-boundaries.md)

## 6. 폴더 연결과 본문 캐시

파일은 ContentResolver 스트림으로 읽고 실제 수신 바이트 수를 제한합니다. 파일 이름·MIME·공급자 크기 정보를 절대적인 정답으로 믿지 않습니다.

**원본 접근 확인 → 전체 해시 검증 → 필요 시 디코딩·인덱스 생성 → 캐시 확정 → 본문 버전 연결** 순서로 처리합니다. 폴더 목록 조회와 본문 준비를 분리하고, 실패가 원본이나 기존 기록을 바꾸지 않게 합니다.

용량을 제한했다고 메모리가 제한되는 것은 아닙니다. ByteArrayOutputStream → ByteArray → String → 문단 리스트로 전체 파일을 연속 복제하지 않습니다. 버퍼·본문 캐시·레이아웃·인덱스에 각각 예산을 둡니다.

외부 원본은 읽기 전용 대상, 파생 본문·인덱스는 재생성 대상, 위치·책갈피는 보존할 기록입니다. 연결 해제·기록 삭제·캐시 정리를 분리하고 오래된 작업이 해제된 연결·삭제한 세션을 되살리지 못하게 합니다.

## 7. 권한·백업·로그

TXT MVP는 SAF 폴더와 내부 캐시·기록 저장소 중심으로 구성합니다. GitHub 업데이트 조회·APK 다운로드에 INTERNET, 사용자 선택에 따른 APK 설치 화면에 REQUEST_INSTALL_PACKAGES를 사용합니다. 알림·전체 파일 접근·캘린더·부팅 수신 권한은 해당 기능 없이 추가하지 않습니다. 본문·독서 기록을 업데이트 서버에 보내지 않습니다.

자동 OS 백업에서는 앱의 연결 정보·캐시·기록을 제외합니다. `allowBackup`과 데이터 추출 규칙을 확인하고 앱 삭제 시 앱 데이터만 사라지며 외부 원본은 유지됨을 안내합니다. 수동 백업 v2에는 EPUB을 포함한 기록과 설정을 저장하며 v1도 가져옵니다. 원본 책·캐시·OS 파일 접근 권한은 수동 백업에 포함하지 않습니다.

오류 로그에는 단계·오류 종류·크기·내부 요청 ID를 우선 남깁니다. 책 본문·앞뒤 문맥·개인 파일명·원본 URI를 통째로 기록하지 않습니다.

## 8. 검사 환경 운영

테스트 데이터는 합성 책과 안정된 ID를 사용합니다. 샘플 추가를 반복해도 기존 책·책갈피·읽기 위치를 덮지 않게 합니다. 검사 전 초기화와 사용자의 수동 확인용 샘플 준비는 별도 명령으로 만듭니다.

시스템 검사는 지정한 개발 패키지와 전용 AVD 이름·시리얼을 확인합니다. 회전·fontScale·화면 유지 설정을 바꾸면 끝날 때 복구합니다. 일반 사용자 기기와 현재 수동 테스트 중인 에뮬레이터를 초기화하지 않습니다.

예상 테스트 목록·실행 결과·JUnit 요약·정상 종료를 함께 확인합니다. ADB 종료 코드만으로 성공 처리하지 않으며 생략·누락·중복·중단은 구분해 기록합니다. 결과 폴더를 실행별로 만들고 실패 로그를 덮지 않습니다.

구체적인 독서 fixture·프레임 측정·프로세스 복구는 [검증 계획](validation-plan.md)을 따릅니다. release 배포 규칙은 [릴리즈 운영](release-workflow.md)에 정리합니다.

EPUB release UI 검사는 fixture를 준비한 전용 AVD에서 `scripts/verify-device.py --serial <serial> --suite epub --variant release --theme LIGHT`로 실행합니다. 다크 모드는 `--theme DARK`입니다. 이 검사는 대상 앱 데이터를 초기화하므로 사용자의 수동 독서용 AVD에서 실행하지 않습니다. `scripts/generate-epub-fixtures.py`가 만든 두 EPUB을 기기의 `Download/YeobaekEPUB`에 복사해야 합니다.

일반 Android 통합 검사는 `EpubSoakTest`를 제외한 목록을 대조합니다. 장시간 검사는 `am instrument -w -r -e class com.poyal.yeobaek.EpubSoakTest -e epubSoakSeconds 1800 com.poyal.yeobaek.debug.test/androidx.test.runner.AndroidJUnitRunner`로 별도 실행합니다. JSON의 `passed`뿐 아니라 instrumentation의 정상 종료·오류 부재까지 확인해야 합니다.
