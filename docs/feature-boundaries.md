# 앱 공통 기능과 형식별 뷰어·옵션 구분

작성일: 2026-10-13. 사용자가 요청한 기능 분리를 반영한 제품·설계 기준입니다. 첫 출시는 **앱 공통 기반 + TXT 뷰어**이며 PDF와 이미지/만화는 후속입니다. 분류표에 있는 후속 기능을 현재 지원하는 것처럼 표시하지 않습니다.

## 1. 서재의 역할

서재는 연결한 OS 폴더 탐색과 최근 읽기를 제공하는 앱 화면입니다. 실제 폴더의 파일을 열고 책별 진행률·기록을 관리합니다. PDF·이미지/만화가 추가되어도 같은 서재를 이용합니다.

서재는 본문을 그리거나 TXT 글꼴을 결정하지 않습니다. 항목을 열면 파일 형식에 맞는 뷰어로 연결하고, 해당 뷰어가 계산한 진행률과 저장한 위치를 사용합니다. 첫 버전에서는 TXT만 열 수 있습니다. 여러 연결 루트·태그·표지 관리 같은 확장은 후속입니다. 기본 폴더 연결과 하위 폴더 탐색은 첫 버전에 포함합니다.

OS 폴더 연결·조회·원본 변경·재연결은 [폴더 연결·서재 설계](folder-library-design.md), 시작 위치와 독서 중 종료 후 확인창은 [시작·이어 읽기 흐름](startup-resume-flow.md)을 따릅니다.

## 2. 기능 소유권

| 구분 | 담당 기능 | 설정·데이터의 적용 범위 | 구현 시점 |
| --- | --- | --- | --- |
| 앱 공통 | 시작 폴더 설정·연결, 하위 탐색·새로고침, 최근 읽기, 기록 삭제·접근 복구, 뷰어 연결, 앱 정보·문의, GitHub 업데이트 | 앱 설정, 폴더 권한·문서 메타데이터, 별도 업데이트 상태 | 첫 출시 |
| 뷰어 공통 기반 | 뒤로·메뉴 틀, 읽기 기록·책갈피, 새 실행 시 이어 읽기 확인, 조작 접근성 | 책 ID와 형식별 위치·책갈피·독서 세션 | 첫 출시부터 재사용 |
| TXT 뷰어 | 인코딩·정규화, 세로 스크롤, 텍스트 배치, 본문 검색, 문자 기준 이동·위치 복원 | TXT 전용 표시 설정과 책별 인코딩 | 첫 출시 |
| PDF 뷰어 | 페이지 렌더링·연속 보기, 확대·이동, 페이지 번호 이동·위치 복원 | PDF 전용 보기 설정 | 후속 |
| 이미지/만화 뷰어 | 이미지·ZIP/CBZ 읽기, 순서 결정, 연속/한 장 보기, 확대·이동·위치 복원 | 이미지/만화 전용 보기 설정과 책별 이미지 목록 | 후속 |

책갈피와 이어 읽기는 저장·목록 기능을 공유합니다. **어디를 저장할지는 각 뷰어가 결정**합니다. TXT는 문자 위치, PDF는 페이지와 페이지 안 좌표, 이미지/만화는 이미지와 이미지 안 좌표입니다. 공통 저장소가 TXT의 줄 번호나 픽셀 좌표를 모든 형식에 강제하지 않습니다.

## 3. 사용자에게 보이는 설정 구조

```text
설정
  앱 설정
    시작 폴더: 현재 경로 표시 / 변경
    앱 화면 테마: 시스템 / 밝게 / 어둡게
    저장 공간·캐시 관리 안내
  TXT 뷰어 설정
    글꼴 / 글자 크기 / 줄간격 / 좌우 여백
    본문 색상: 앱 테마 따르기 / 밝게 / 어둡게 / 세피아
    TXT 설정 기본값 복원
  PDF 뷰어 설정                 PDF 구현 후 표시
    페이지 맞춤 / 페이지 간격 / 바깥 배경
    PDF 설정 기본값 복원
  이미지·만화 뷰어 설정         해당 뷰어 구현 후 표시
    연속 보기·한 장 보기 / 한 장 보기의 넘김 방향
    화면 맞춤 / 이미지 간격 / 바깥 배경
    이미지·만화 설정 기본값 복원
```

첫 출시에 표시하는 설정 그룹은 앱과 TXT입니다. 미래 PDF·이미지 메뉴를 빈 화면이나 비활성 홍보 메뉴로 미리 노출하지 않습니다. 저장 공간의 별도 관리 UI는 구현 범위를 정해 추가하며, 초기에는 연결 해제·독서 기록 삭제·캐시 정책 안내를 제공합니다. 외부 파일은 삭제하지 않습니다.

독서 중 설정 버튼을 누르면 **현재 형식의 설정만** 엽니다. TXT의 글자 크기를 바꿔도 PDF·이미지에는 영향이 없고, 이미지의 넘김 방향을 바꿔도 TXT의 스크롤 방식은 유지됩니다. PDF·이미지 뷰어에 글꼴·인코딩 옵션을 노출하지 않습니다.

앱 테마는 서재·앱 설정·보조 시트에 적용합니다. TXT 본문 색상은 독립된 옵션입니다. `앱 테마 따르기`는 현재 앱 테마를 참조하며, 고정한 밝게·어둡게·세피아 값은 앱 테마 변경으로 덮어쓰지 않습니다. 독서 툴바와 시스템 바는 실제 본문 색상에 맞춥니다. PDF·이미지의 바깥 배경을 바꾸는 동작은 페이지·그림 자체의 색 변환과 다릅니다. 색 반전은 첫 형식별 버전의 필수 기능에 포함하지 않습니다.

## 4. 형식별 옵션과 책별 정보

| 대상 | 전용 옵션·동작 | 후속 검토 |
| --- | --- | --- |
| TXT | 글꼴·크기·줄간격·좌우 여백·본문 색상, 인코딩 미리보기·변경, 문자 진행률 이동·본문 검색 | 페이지 모드, 문장 선택·형광펜, TTS, 사용자 폰트, 자동 줄바꿈 정리 |
| PDF | 세로 연속 보기, 페이지/폭 맞춤, 페이지 간격·바깥 배경, pinch 확대·페이지 이동 | 좌우 넘김, 두 쪽 보기, 여백 자르기, 색 반전; 검색·선택·암호 문서는 엔진 확인 후 범위 결정 |
| 이미지/만화 | 세로 연속/한 장 보기, 한 장 보기의 좌→우·우→좌 넘김, 화면/폭 맞춤, 간격·바깥 배경, 확대·이미지 이동 | 두 장 보기·표지 예외·자동 여백 자르기·이미지 보정·OCR |

인코딩은 모든 TXT에 적용할 외관 설정이 아니라 **해당 책의 본문 해석 정보**입니다. A책의 인코딩을 바꿔도 B책을 재해석하지 않습니다. PDF 암호와 이미지 파일 순서도 도입 시 해당 문서의 정보로 다룹니다.

표시 설정은 초기에는 형식별 기본값으로 저장합니다. TXT에서 변경한 글자 크기는 다른 TXT에도 적용되지만 PDF·이미지에는 적용되지 않습니다. 같은 형식 안에서도 책마다 따로 꾸미는 기능은 후속으로 둡니다. 도입하면 `앱이 제공한 형식 기본값 → 사용자 형식별 기본값 → 해당 책의 명시적 재정의` 순서로 해석합니다.

`TXT 설정 기본값 복원`은 TXT 외관 값만 초기화합니다. 앱 테마·PDF/이미지 설정·책별 인코딩·읽기 위치·책갈피는 유지합니다. 폴더 연결 해제, 독서 기록 삭제, 캐시 정리, 표시 설정 초기화는 서로 다른 동작입니다.

## 5. 저장·코드 경계

아래는 모델 경계 제안이며 현재 존재하는 코드가 아닙니다.

```text
설정 저장소
  AppPreferences        시작 폴더 연결 ID, 앱 UI 테마
  TxtPreferences        font, size, lineHeight, margin, colorScheme
  PdfPreferences        fitMode, pageSpacing, canvasColor       [후속]
  ImagePreferences      viewMode, pageTurnDirection, fitMode,
                        imageSpacing, canvasColor               [후속]

책 메타데이터·기록 저장소
  FolderConnection      treeUri, provider authority, rootDocumentId
  Book                  id, format, documentId, documentUri, lastVerifiedHash
  TextContent           bookId, charset, contentVersion
  ReadingSessionState   새 실행에서 확인할 독서 중 종료 후보
  ReadingPosition       bookId, contentVersion, locatorVersion, 형식별 Locator
  Bookmark              bookId, locatorVersion, 형식별 Locator
```

DataStore를 하나로 시작하더라도 형식별 타입·키 영역·갱신 함수를 나눕니다. 전체 설정을 과거 값으로 덮는 `saveAll` 대신 `updateTxtPreferences`, `resetTxtPreferences`처럼 변경 범위를 제한합니다. 각 뷰어는 자기 설정의 변경만 관찰하여 다른 형식의 설정 변경으로 레이아웃을 다시 계산하지 않습니다.

TXT의 charset은 Room의 책 정보에, 표시 설정은 TXT 설정 저장소에 둡니다. 모든 옵션을 nullable 필드로 모은 하나의 `ReaderPreferences`나, 모든 형식에 글자 크기 변경을 요구하는 공통 API는 만들지 않습니다.

공통 뷰어 계약은 문서 열기·닫기, 형식에 맞는 Locator로 이동, 현재 Locator·진행률·사용 가능한 기능 보고 정도로 제한합니다. 공통 메뉴는 검색·선택·확대·읽기 방향의 지원 여부를 현재 엔진과 문서에서 확인하고, 각 뷰어는 자신의 설정 패널을 제공합니다. 예를 들어 스캔 PDF에 텍스트 검색을 보장하거나 이미지에 TXT 검색 버튼을 붙이지 않습니다.

논리 경계를 나누기 위해 미래 Gradle 모듈·저장 모델을 모두 미리 구현하지 않습니다. 첫 버전에서는 AppPreferences·TxtPreferences와 공통 기록 계약을 구현하고, PDF·이미지 설정은 해당 뷰어를 개발할 때 추가합니다.

## 6. 분리가 완료되었다고 판단할 조건

1. 첫 출시의 설정에는 앱 설정과 TXT 설정만 있고, 독서 설정은 TXT 옵션만 표시합니다.
2. TXT 글자 크기·색상 변경과 초기화가 시작 폴더·앱 테마·읽기 기록·책갈피·책별 인코딩을 바꾸지 않습니다.
3. 앱 화면 테마 변경이 사용자가 지정한 TXT 본문 색상을 덮지 않습니다.
4. A책의 인코딩을 바꿔도 B책의 인코딩과 위치는 그대로 유지합니다.
5. 후속 뷰어가 추가되면 TXT→PDF→이미지→TXT 왕복 후 각 형식의 설정과 각 책의 위치가 유지됩니다.
6. PDF·이미지의 설정 초기화와 새 설정 스키마 추가가 기존 TXT 설정·기록을 지우지 않습니다.
7. 현재 형식·문서가 제공하지 않는 기능은 메뉴에 나타나지 않고, 일시적인 준비·실패 상태는 지원 불가와 구별합니다.

전체 구현 순서는 [개발 계획](../plan.md), TXT 내부 처리와 좌표는 [TXT 기술 설계](txt-reader-design.md), 후속 엔진은 [형식 확장 조사](format-roadmap.md)를 따릅니다.
