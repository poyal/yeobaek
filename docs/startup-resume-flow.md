# 시작 폴더 설정과 이어 읽기 확인

작성일: 2026-10-13. 앱 공통 사용자 흐름입니다. TXT부터 적용하고 PDF·이미지/만화에도 같은 흐름을 사용합니다.

## 1. 확정할 동작

- 앱 설정에서 시작 폴더를 선택·변경할 수 있습니다.
- 앱을 새로 실행하면 항상 설정한 시작 폴더가 기본 탐색 화면입니다.
- 책을 읽다가 앱을 종료한 경우, 다음 실행에 `이어서 읽으시겠습니까?`를 묻습니다.
- `이어서 읽기`를 선택하면 해당 형식의 뷰어가 마지막 저장 위치를 복원합니다.
- `폴더 보기`를 선택하면 시작 폴더를 표시하고, 위치·책갈피·최근 읽기 기록은 유지합니다.

## 2. 설정과 폴더 연결

```text
설정 > 앱 설정
  시작 폴더
  Books / 소설                         [변경]
  앱을 시작할 때 이 폴더를 엽니다.
```

최초 실행에는 OS 폴더 선택기를 열어 시작 폴더를 지정합니다. 선택한 tree URI의 영속 읽기 권한과 실제 조회를 확인한 뒤 설정을 저장합니다. 변경 도중 취소·권한 확보 실패·조회 실패가 생기면 이전 시작 폴더를 유지합니다.

첫 버전은 시작 폴더 하나를 연결 루트로 사용합니다. 그 아래를 탐색해도 시작 폴더 설정은 그대로입니다. 단순 회전·같은 실행의 화면 복원은 현재 폴더를 유지하고, 새 앱 진입에서는 시작 폴더를 엽니다. 시작 폴더를 바꿔도 다른 책의 읽기 기록을 삭제하지 않습니다.

## 3. 시작 시 화면 결정

| 상태 | 처리 |
| --- | --- |
| 시작 폴더를 설정한 적 없음 | 폴더 설정 안내 |
| 시작 폴더 설정 있음, 독서 중 종료 기록 없음 | 시작 폴더 목록 |
| 시작 폴더 설정 있음, 독서 중 종료 기록 있음 | 시작 폴더 화면 위에서 이어 읽기 확인 |
| 시작 폴더 접근 실패 | 재연결 상태를 표시하고 설정을 보존; 이어 읽기 후보가 있으면 확인은 표시하되 실제 접근은 검증 |
| 후보 책의 원본 접근 실패 | 재연결·파일 다시 지정 안내와 폴더 보기; 위치·책갈피 보존 |
| 후보 책의 내용 변경 | 새 본문 확인과 위치 이전 절차 후 열기; 과거 오프셋을 새 내용에 바로 적용하지 않음 |

```text
이어서 읽으시겠습니까?

작품 B.txt
마지막 읽은 위치 42.3%

[폴더 보기]                   [이어서 읽기]
```

확인창에는 파일명과 마지막 저장 진행률을 표시합니다. 준비 전에는 진행률이 없을 수 있으므로 임의의 퍼센트를 만들지 않습니다. 최근 읽은 시간은 보조 정보로 사용할 수 있습니다.

`이어서 읽기` 선택 후 원본 검증·캐시 준비 중에는 중복 탭을 막고 취소할 수 있게 합니다. 오류가 나면 그대로 재시도하거나 폴더로 돌아갈 수 있습니다. 확인창을 닫거나 뒤로 가기를 누르면 `폴더 보기`와 같은 의미로 처리합니다.

## 4. 언제 확인할 것인가

앱 종료 콜백만으로 다음 동작을 결정하지 않습니다. 프로세스가 갑자기 종료되면 콜백 없이 끝날 수 있으므로, 성공적으로 뷰어에 진입한 시점부터 **현재 독서 세션이 활성 상태임을 저장**합니다.

| 이벤트 | 저장·표시 정책 |
| --- | --- |
| 본문 준비·복원 완료 후 뷰어 진입 | 해당 bookId를 다음 실행의 이어 읽기 후보로 기록 |
| 독서 중 스크롤 | 기존 주기 저장으로 Locator·진행률 갱신 |
| 홈으로 이동·앱 전환·화면 잠금 | 최종 저장 시도, 후보 유지; 같은 뷰어로 돌아오면 팝업 없이 계속 읽기 |
| Activity 회전·설정 변경 재생성 | 현재 화면 복원; 시작 확인을 반복하지 않음 |
| 사용자가 뷰어의 뒤로 가기로 폴더에 복귀 | 위치 저장 후 활성 후보 해제; 최근 읽기 기록은 유지 |
| 독서 중 프로세스 종료·작업 제거 후 새 실행 | 남은 후보로 한 번 확인 |
| 서재에서 종료 후 새 실행 | 시작 폴더 표시; 과거 책이 있다는 이유만으로 반복 확인하지 않음 |
| 확인창에서 폴더 보기 | 후보 소비·해제; 책의 위치·책갈피·최근 기록은 유지 |
| 확인창에서 이어서 읽기 성공 | 새 독서 세션을 활성 후보로 기록 |

프로세스 종료 여부와 종료 이유를 정확히 추정하는 기능은 만들지 않습니다. 영속된 후보는 사용자가 마지막으로 독서 화면에 있었는지를 나타냅니다. 강제 종료 직전 마지막 저장 주기 안의 위치는 저장되지 않았을 수 있습니다.

새 실행 여부는 단순한 `Activity.onCreate` 횟수로 판정하지 않습니다. 시작 흐름 조정자가 새 작업/프로세스 진입과 현재 화면 재생성을 구분합니다. 프로세스 종료 후 SavedState에 Reader 경로가 남아 있어도 새 진입에서는 확인 절차를 우회해 본문을 자동 표시하지 않습니다.

## 5. 상태와 비동기 처리

```text
AppPreferences
  startFolderConnectionId
ReadingSessionState
  candidateBookId?, sessionRevision, updatedAt
ReadingPosition
  bookId, locatorVersion, locatorPayload, updatedAt
StartupUiState
  launchId, phase, promptHandled, pendingOpenRequestId?
```

시작 폴더 설정과 이어 읽기 후보는 서로 다른 정보입니다. 후보와 위치는 Room에서 관리해 같은 세션의 저장 순서를 통제합니다. `폴더 보기`·기록 삭제·명시적 독서 종료가 소비한 후보를 이전 세션의 늦은 저장이 다시 활성화하지 못하게 합니다. 후보 활성화는 뷰어 진입 사건에서만 하고 주기 위치 저장은 후보를 새로 만들지 않습니다.

시작 폴더 변경과 권한 보존은 Room·DataStore·OS 사이에 단일 트랜잭션이 아닙니다. 새 연결 준비 → 시작 설정 변경 → 더 이상 사용하지 않는 이전 권한 정리 순서로 처리하고 중단 시 복구합니다. 현재 연결 외부의 과거 책을 다시 열 때는 필요한 권한을 재요청합니다.

한 번의 새 진입에서는 확인창을 한 번만 표시합니다. 확인창 표시 중 회전은 동일 상태로 복원하고, 이미 처리한 확인창이 느린 DB 조회나 오래된 요청 완료 때문에 다시 나오지 않도록 `launchId`·요청 순번을 검사합니다. 미래 형식도 `bookId → format → 해당 뷰어 → Locator 복원`으로 동일한 흐름을 따릅니다.

## 6. 검증 조건

1. A 폴더를 시작으로 지정하고 B 하위 폴더를 탐색한 뒤 앱을 새로 실행하면 A가 열립니다.
2. 시작 폴더 변경 취소·권한 실패 뒤에도 기존 설정과 접근이 유지됩니다.
3. TXT를 42%까지 읽다가 종료하면 다음 새 실행에 해당 책 확인창이 한 번 표시됩니다.
4. 이어서 읽기를 선택하면 마지막 저장 문장을 복원하고, 폴더 보기를 선택하면 시작 폴더로 이동합니다.
5. 폴더 보기를 선택한 뒤 다시 실행하면 같은 후보를 반복해서 묻지 않습니다. 최근 읽기에서 직접 여는 기능은 유지됩니다.
6. 회전·화면 잠금·짧은 앱 전환 후 복귀에는 시작 확인창이 중복 표시되지 않습니다.
7. 원본 이동·삭제·수정, SD카드 분리, 시작 폴더 권한 상실에서 데이터가 보존되고 재연결로 복구합니다.
8. 빠른 책 전환·확인창 연속 탭·기록 삭제와 늦은 위치 저장이 겹쳐도 잘못된 후보가 다시 활성화되지 않습니다.

폴더 접근·원본 검증은 [폴더 연결 설계](folder-library-design.md), 형식별 위치 복원은 [TXT 기술 설계](txt-reader-design.md)를 따릅니다.
