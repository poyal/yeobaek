# 제품 및 UX 사전조사

조사일: 2026-10-13. 범위와 우선순위는 [plan.md](../plan.md)를 따릅니다.

## 1. 사용자 요구의 해석

사용자께서는 Android의 아라·리디 같은 전자책 뷰어를 원하셨고, TXT부터 구현하되 **조아라·노벨피아처럼 부드럽게 스크롤되는 경험**을 구체적으로 요청하셨습니다.

따라서 첫 화면의 목표는 “TXT 파일의 내용을 보여주기”보다 한 단계 높습니다. 한 손으로 천천히 읽거나 빠르게 훑어도 끊기지 않고, 다시 열면 읽던 문장으로 돌아오는 독서 도구를 만듭니다. 웹소설 플랫폼의 회원·결제·회차 서버·댓글은 이 요구에 포함되지 않습니다.

## 2. 참고 서비스에서 확인한 내용

공개 소개와 지원 문서를 확인했습니다. 직접 설치하여 동작이나 성능을 비교한 결과는 아닙니다.

| 대상 | 공식 자료에서 확인한 내용 | 여백에 적용할 판단 |
| --- | --- | --- |
| 아라 | TXT·PDF·이미지·압축파일을 열며 글꼴·간격·여백, 인코딩 수정, 책갈피, 검색과 여러 이동 방식을 제공합니다. [Google Play](https://play.google.com/store/apps/details?id=noad.geulga&hl=ko) | 로컬 파일 읽기에 필요한 기능 목록을 참고합니다. 초기 버전에 모든 형식과 조작을 담지 않습니다. |
| 리디 | 독서노트 기능을 제공하며, PDF에서는 플랫폼에 따라 글자 크기·검색·노트 등 기능에 제한이 있습니다. [이용 안내](https://ridihelp.ridibooks.com/support/solutions/articles/154000207726), [형식별 제한](https://ridihelp.ridibooks.com/support/solutions/articles/154000207702) | 본문 중심 화면을 지향하고, 형식별 가능한 기능만 표시합니다. |
| 조아라 | 공식 Android 앱 소개에서 읽기 환경을 조절하는 웹소설 뷰어를 설명합니다. [Google Play](https://play.google.com/store/apps/details?id=com.joara.mobile&hl=ko) | 연속 독서와 간단한 읽기 설정을 참고합니다. |
| 노벨피아 | 공식 Android 앱 소개에서 웹소설 열람·다운로드·TTS를 설명합니다. [Google Play](https://play.google.com/store/apps/details?id=com.novelpia.android.me&hl=ko) | 로컬 원본에 접근 가능한 동안 오프라인으로 읽는 흐름을 중시합니다. TTS는 후속 기능입니다. |

위 자료로 각 서비스의 내부 렌더러, 블록 크기, 관성 곡선, 프레임 수치는 알 수 없습니다. 별점·리뷰 수를 성능이나 UX 품질의 증거로 쓰지 않습니다.

## 3. “부드러움”을 동작으로 정의하기

| 사용 상황 | 기대하는 결과 | 눈에 보이는 실패 |
| --- | --- | --- |
| 손가락으로 천천히 밀기 | 본문이 손가락 움직임에 따라 연속적으로 이동합니다. | 일정 구간마다 미세하게 멈춥니다. |
| 빠른 플링 후 손 떼기 | 기본 관성이 자연스럽게 줄어들며 멈춥니다. | 멈추었다가 갑자기 더 이동합니다. |
| 아직 보지 않은 부분으로 이동 | 다음 본문이 준비되어 자연스럽게 이어집니다. | 흰 영역이 오래 보이거나 글이 늦게 솟아납니다. |
| 반대 방향으로 다시 이동 | 방금 읽은 위치를 즉시 보여줍니다. | 캐시를 잃어 같은 구간에서 다시 멈춥니다. |
| 메뉴 표시·숨기기 | 본문 너비와 현재 문장 위치가 유지됩니다. | 툴바 높이만큼 본문 전체가 밀립니다. |
| 글자 크기 변경 | 같은 문장을 기준으로 새 줄바꿈을 적용합니다. | 책 앞부분이나 전혀 다른 문단으로 이동합니다. |
| 오래 읽기 | 메모리 사용과 발열이 계속 증가하지 않습니다. | 시간이 지날수록 스크롤이 무거워집니다. |

평균 FPS와 짧은 시연만으로 완료 판정하지 않습니다. [측정 절차](validation-plan.md)의 새 블록 진입·역방향 이동·긴 읽기 구간을 확인합니다.

## 4. 첫 버전 화면

첫 버전은 앱 공통 화면과 TXT 뷰어를 함께 제공합니다. 폴더 연결·최근 읽기·시작 폴더 설정은 공통 기능이며, 본문·인코딩·텍스트 검색·표시 옵션은 TXT 기능입니다. 상세 소유권은 [기능·설정 분리](feature-boundaries.md)를 따릅니다.

### 서재와 시작 폴더 — 앱 공통

첫 실행에서 OS 폴더 선택기로 시작 폴더를 연결합니다. 이후 새 실행은 설정한 폴더를 열며, 같은 실행에서 하위 폴더를 탐색한 사실만으로 시작 위치가 바뀌지 않습니다. 앱 설정에서 시작 폴더를 변경할 수 있습니다.

서재는 실제 폴더·파일 목록과 최근 읽기를 구분합니다. 폴더 목록은 폴더 우선·파일명 순서, 최근 읽기는 마지막 열람 순서입니다. 파일 항목에는 원래 이름·형식·읽은 진행률을 표시합니다. 연결 시 전체 파일을 복사·인덱싱하지 않습니다. [폴더 연결·서재 설계](folder-library-design.md)

### 독서 중 종료한 다음 실행 — 뷰어 공통

읽던 책의 제목·마지막 저장 진행률과 `이어서 읽기` / `폴더 보기` 확인을 표시합니다. 전자는 원본을 확인하고 해당 뷰어로 복원하며, 후자는 시작 폴더를 열고 기존 기록은 보존합니다. 독서 화면에서 명시적으로 폴더로 돌아온 뒤 종료했다면 다음 실행에 같은 확인을 반복하지 않습니다. 회전·잠깐의 앱 전환도 확인 대상이 아닙니다. [시작·이어 읽기 흐름](startup-resume-flow.md)

### 파일 열기 — 공통 접근 / 인코딩 미리보기 — TXT 전용

```text
연결 폴더 → 파일 탭 → 원본 접근·내용 확인
                       ├─ 같은 내용·유효 캐시 → TXT 뷰어
                       ├─ 캐시 없음·내용 변경 → 인코딩·본문 준비 → TXT 뷰어
                       └─ 접근 실패 → 재연결 또는 폴더 보기
```

파일을 열 때만 원본을 검증하고 필요한 읽기 캐시를 준비합니다. 크기 미상 공급자에는 가짜 백분율 대신 처리 중 표시를 사용합니다. 원본은 외부 폴더에 두며, 로컬 파일은 접근 가능한 동안 인터넷 없이 읽을 수 있습니다. 클라우드 공급자는 네트워크에 의존할 수 있습니다.

처음 열 때 자동 판정하며, `글자가 깨져 보이나요?`에서는 UTF-8·CP949·EUC-KR·UTF-16 LE/BE를 수동으로 미리 보고 선택합니다. 인코딩은 해당 책에 적용하며 개발자용 오프셋·예외 클래스는 기본 화면에 표시하지 않습니다. 실제 파일의 이름·내용 변경과 접근 실패가 과거 기록을 삭제하지 않도록 합니다.

### TXT 본문

기본은 세로 한 단, 연속 스크롤입니다. 카드·페이지 테두리·문단별 구분선을 넣지 않습니다. 원본 빈 줄은 보존합니다.

- 가운데 한 번 탭하면 메뉴를 표시하거나 숨깁니다.
- 드래그와 플링은 메뉴 탭으로 오인하지 않도록 플랫폼의 터치 판정을 사용합니다.
- 첫 버전에서 좌우 화면 탭은 페이지 이동을 수행하지 않습니다.
- 상단은 뒤로·제목·책갈피, 하단은 진행률·검색·읽기 설정을 배치하는 안을 시제품으로 확인합니다.
- 메뉴는 본문 위의 오버레이로 표시하되 안전 영역을 확보하고 활성 버튼만 터치를 받습니다.
- 진행률은 `42.3%`와 같이 표시하며 전체 페이지 수를 계산하지 않습니다.
- 본문 끝에는 끝에 도달했음을 알려주고, 다시 위로 읽는 동작을 막지 않습니다.

### 앱 설정과 TXT 읽기 설정

앱 설정에는 시작 폴더와 서재·메뉴 UI의 테마를 두고, TXT 설정에는 본문 표시 옵션을 둡니다. 독서 중 설정 버튼은 TXT 옵션만 엽니다. PDF·이미지/만화의 설정은 해당 뷰어 구현 시 독립된 그룹으로 추가합니다.

아래는 확정 디자인과 현재 구현에 적용한 기본값입니다. 실제 기기에서 한글·혼합 문장과 큰 시스템 글자 크기의 읽기 품질은 별도로 인수합니다.

| 항목 | 기본값 후보 | 정책 |
| --- | --- | --- |
| 글자 크기 | 18sp | 앱 설정 범위 14~32sp부터 검증하며 시스템 fontScale도 반영합니다. |
| 줄간격 | 글자 크기의 1.85배 | 1.3~2.1배를 지원합니다. 글리프 잘림을 검증합니다. |
| 좌우 여백 | 24dp | 16~40dp를 지원하며 좁은 창에서는 유효 폭을 확보합니다. |
| 글꼴 | 명조 18sp | 확정 디자인에 따라 Noto Serif CJK KR을 번들로 제공하고 시스템 고딕을 선택할 수 있습니다. |
| TXT 본문 색상 | 앱 테마 따르기 | 밝게·어둡게·세피아를 직접 선택할 수 있습니다. 앱 UI 테마와 독립 저장하고 오버레이 조합도 검증합니다. |
| 문단 정렬 | 왼쪽 정렬 | 양쪽 정렬·자동 문장 합치기는 후속입니다. |

앱 UI의 글자 크기와 본문 읽기 설정을 분리합니다. 본문 설정 때문에 메뉴 글자가 작아지지 않아야 합니다. 슬라이더 조작은 현재 화면만 재배치하며 지나간 요청을 취소하고 마지막 값을 반영합니다.

표시 옵션은 TXT끼리 공유하는 기본값입니다. TXT 기본값 복원은 해당 표시 옵션만 바꾸고 시작 폴더·앱 테마·책별 인코딩·위치·책갈피는 유지합니다. 인코딩 선택은 현재 책에만 적용합니다.

### 책갈피 — 공통 저장·TXT 위치 해석 / 본문 검색 — TXT 전용

책갈피는 화면 상단의 읽기 기준 문장에 저장하며 짧은 본문 미리보기를 보여줍니다. 페이지 번호는 사용하지 않습니다.

검색은 정확한 부분 문자열부터 시작합니다. 단어 중간의 부분 문자열과 블록 경계에 걸친 검색을 지원하고, 정규식·초성 검색·검색용 형태소 분석은 후속으로 둡니다. 검색 결과를 눌렀을 때 대상 문장이 보이도록 이동하며 뒤로 가면 원래 읽기 위치로 복귀할 수 있게 탐색 전 위치를 보관합니다.

## 5. 오류와 복구 UX

| 조건 | 사용자에게 보여줄 대응 |
| --- | --- |
| 폴더 선택·변경 취소 | 기존 설정 유지, 최초 설정 전이면 연결 안내로 돌아가기 |
| 시작 폴더 선택 제한·권한 상실 | 선택 가능한 폴더 안내·재연결; 설정을 다른 경로로 임의 변경하지 않음 |
| SD카드 분리·공급자 연결 실패 | 다시 연결 후 재시도; 삭제된 파일로 단정하지 않음 |
| 빈 TXT | 내용이 없음을 안내; 실제 폴더의 파일은 그대로 유지 |
| 미지원 형식 | 첫 버전의 TXT 지원 안내 |
| 깨진 한글·자동 판정 불확실 | 인코딩 미리보기 |
| 원본 내용 변경 | 새 본문 확인, 이전 위치·책갈피 보존과 문맥 기반 이전 |
| 저장 공간 부족·용량 초과 | 해당 준비 작업 임시 데이터 정리, 원본·기록 유지 |
| 파생 캐시 손상·삭제 | 원본 접근 확인 후 재생성, 기록 유지 |
| 원본 이동·삭제 | 재연결·파일 다시 지정 또는 폴더 보기; 기록은 자동 삭제하지 않음 |

폴더 연결 해제·독서 기록 삭제·캐시 정리는 별도 동작입니다. 기록 삭제는 확인 후 해당 위치·책갈피·최근 기록만 지우고 폴더의 파일은 유지합니다. 외부 파일 삭제·이름 변경은 첫 버전에서 제공하지 않습니다.

## 6. 출시 후 확인할 사용성 질문

시제품을 실제로 읽으면서 기본 글자 크기와 줄간격, 가운데 탭의 편의성, 메뉴의 가림 정도, 인코딩 선택의 이해도, 검색 후 읽기 복귀를 확인합니다. 페이지 모드·볼륨 키·TTS는 이 피드백 이후 순서를 정합니다.

공통 컴포넌트·큰 글씨·키보드·본문 위치 보존 규칙은 여백의 [UI 기준](ui-guidelines.md)에 정리합니다. 입력용 공통 페이지와 독서 본문은 별도로 구성합니다.
