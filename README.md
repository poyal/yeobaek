# 여백 · yeobaek

Android에서 기기의 TXT·PDF와 이미지 폴더·압축파일을 읽는 앱입니다. **종이의 여백** 화면과 **리듬** 아이콘을 라이트·다크 모드로 구현했습니다. Android 11 이상을 지원하는 개인용 독서 앱입니다. 과거 에뮬레이터 프레임 목표는 미달이며 실물 성능·TalkBack 인수는 남아 있습니다.

**[최신 공개 APK 다운로드](https://github.com/poyal/yeobaek/releases/latest)** · [v0.2.0 변경 사항](docs/releases/v0.2.0.md) · [0.2.0 릴리즈 검증](docs/releases/0.2.0-verification.md) · [문의·오류 신고](https://github.com/poyal/yeobaek/issues)

현재 공개 버전은 **v0.2.0**입니다. PDF·이미지 뷰어와 완독 후 다음 항목 읽기, 공통 메뉴 개편을 포함합니다. 기존 v0.1.0과 같은 서명으로 배포하며, 앱을 삭제하지 않고 업데이트하면 독서 기록과 설정이 유지됩니다.

현재 개발 코드에는 홈 화면 아이콘 축소, 시스템 글꼴·굵기 선택 확장, TXT 본문 교체 시 읽기 위치 보존과 스크롤 진단 로그가 추가되어 있습니다. 아직 공개 APK에 포함된 변경은 아닙니다. 개발 빌드에서 문제가 생기면 **설정 → 앱 정보·문의 → 스크롤 진단 로그 저장**으로 파일을 저장하고 재현한 날짜·시분과 함께 전달할 수 있습니다. 로그는 기기에 최대 128MiB를 보관하며 책 이름·본문은 기록하지 않습니다. [구조와 검증](docs/implementation.md#txt-글꼴과-스크롤-진단)

## 사용하기

개발 빌드에는 **빠른 읽기 설정**, 공통·폴더·책별 항목 단위 설정, 독서 화면 밝기·회전·화면 유지, 만화 펼침면 분할·여백 자르기, 폴더 검색·정렬·즐겨찾기·진행 표시, 수동 기록 백업과 외부 앱에서 열기가 추가되어 있습니다. EPUB와 TXT 자동 목차는 포함하지 않습니다. [에뮬레이터 화면 보고서](docs/reader-upgrade-report/index.html)

독서 중 **설정**을 누르면 빠른 조절 창이 열리고 **자세한 읽기 설정**에서 전체 옵션을 바꿀 수 있습니다. 설정은 `책 → 바로 위 폴더 → 형식별 공통값` 순으로 적용하며 개별 변경 항목의 **상속**을 누르면 공통값을 다시 따릅니다. 하위 폴더에는 자동 전파하지 않습니다.

**설정 → 일반 설정 → 독서 기록 백업**에서 위치·책갈피·설정·즐겨찾기를 JSON 파일로 저장하거나 가져옵니다. 원본 책과 캐시·진단 로그는 제외합니다. 가져오기는 기존 값을 유지하면서 없는 기록만 추가하며, 다른 기기의 파일은 다시 연결해야 합니다.

1. 기기에 책 폴더를 만들고 TXT·PDF·이미지 또는 ZIP/CBZ·RAR/CBR·7Z/CB7을 넣습니다. 처음 실행에서 **시작 폴더 선택**을 누르고 Android 폴더 선택기에서 해당 폴더를 연결합니다.
2. 폴더와 하위 폴더에서 파일을 누르면 읽기를 준비합니다. 파일은 원래 위치에 유지되며 앱은 원본을 수정하거나 삭제하지 않습니다.
3. 본문을 위아래로 스크롤합니다. 본문을 짧게 누르면 상단·하단 메뉴가 함께 숨겨지고, 다시 누르면 나타납니다.
4. 상단에서 진행률과 책갈피를 확인합니다. 하단 **이동**에서 목표 위치를 고른 뒤 적용합니다. 취소하면 기존 위치가 유지됩니다.

5. **읽기 설정**에서 명조/고딕, 크기, 행간, 여백, 본문 색상을 바꿉니다. 앱의 라이트·다크 설정과 TXT 본문 색상은 별도로 저장됩니다.
6. **검색**으로 문장을 찾고 이전/다음 결과나 원래 위치로 이동합니다. **책갈피**는 문장 위치를 저장하고 목록에서 이동·삭제할 수 있습니다.
7. 독서 중 앱을 닫았다가 새로 실행하면 이어 읽기를 묻습니다. **폴더 보기**를 선택하거나 독서 화면의 뒤로 가기로 나오면 다음 실행은 설정한 시작 폴더에서 시작합니다.
8. 글자가 깨지면 **책 정보 → 글자가 깨져 보이나요?**에서 인코딩을 미리 보고 적용합니다. 파일을 옮겨 접근할 수 없으면 **파일 다시 찾기**로 기록을 재연결합니다.

앱의 하단 탐색은 **홈 · 최근 읽기 · 설정**입니다. 세 뷰어의 하단 메뉴는 **이동 · 책갈피**로 시작하고 **설정**으로 끝납니다. 가운데에는 TXT의 검색·정보, PDF의 검색·색상 반전, 이미지의 색상 반전이 표시됩니다. 아이콘뿐 아니라 라벨과 주변 영역도 눌러 사용할 수 있습니다.

**설정 → 일반 설정**에서 시작 폴더와 앱 테마를 바꿀 수 있습니다. 그 안의 **폴더와 저장 공간**에서는 시작 폴더 변경·연결 해제·읽기 캐시 정리를 제공합니다. **설정 → 뷰어 설정**에서는 TXT·PDF·이미지 각각의 읽기 설정을 바꿉니다. 최근 읽기의 **독서 기록 관리**는 위치와 책갈피만 삭제합니다. 원본 파일은 유지됩니다.

**설정 → 앱 정보·문의**에서 제작자, 이메일, GitHub, 오류 신고와 변경 내역을 확인할 수 있습니다. **설정 → 업데이트**에서는 최신 공개 버전을 확인하고 APK를 Download 폴더에 저장합니다. 새 실행의 자동 확인은 하루 한 번이며 수동 확인도 가능합니다. 공개 릴리즈가 없거나 연결에 실패하면 그 상태를 안내합니다.

다운로드한 APK는 크기·SHA-256을 확인하고, 설치 직전에 앱 ID·버전·서명을 검증합니다. **업데이트 설치**에서 Android의 ‘이 출처의 앱 설치 허용’을 켠 다음 설치 버튼을 다시 누릅니다. 앱을 삭제하지 않고 같은 서명의 새 APK로 업데이트해야 독서 기록이 유지됩니다. 설치가 취소되거나 끝나도 다운로드한 APK는 자동 삭제하지 않습니다. 업데이트 통신에 본문·책갈피·읽기 기록은 포함하지 않습니다.

## 지원 범위

- UTF-8, UTF-16 LE/BE, CP949, EUC-KR. BOM 없는 UTF-16 등 자동 판정이 어려운 파일은 수동 인코딩을 선택합니다.
- TXT 원본 100MiB 안전 한도, 정규 본문 256MiB, 검색 결과 인덱스 32MiB. 대용량은 본문 전체를 메모리에 올리지 않습니다.
- PDF는 세로 연속 스크롤, 핀치·두 번 탭 확대, 너비/페이지 맞춤, 페이지 이동·책갈피·이어 읽기, 텍스트 검색·선택·복사를 지원합니다. 하단 **색상 반전**은 이미지와 도표를 포함한 페이지 전체를 반전하며 원본을 바꾸지 않습니다.
- PDF 스캔 페이지는 표시할 수 있지만 OCR은 제공하지 않습니다. 좌우 페이지 넘김·두 쪽 보기·편집·주석·서명·암호 문서 열기는 현재 지원하지 않습니다. EPUB·TTS·동기화도 지원 범위에 포함되지 않습니다.
- 이미지를 누르면 같은 폴더의 이미지들을 선택한 파일부터 읽습니다. 압축파일은 내부 하위 폴더를 포함한 한 권으로 열며 파일명 숫자 순서대로 정렬합니다. JPG/JPEG·PNG·WebP·BMP·GIF(첫 프레임)를 지원합니다.
- 이미지 뷰어는 세로 연속/좌우 넘김, 양방향 읽기, 한 쪽/두 쪽/가로 화면 자동 배치, 표지 한 쪽 옵션, 확대, 썸네일·목차·번호 이동, 책갈피·이어 읽기와 색상 반전을 제공합니다. 설정은 전체 화면이며 TXT·PDF와 독립적입니다.
- TXT·PDF·이미지를 끝까지 읽으면 **다음 것 보기 / 나가기**를 안내합니다. 세로 읽기는 끝에서 스크롤이 멈춘 뒤, 이미지 좌우 넘김은 마지막 장에서 한 번 더 넘길 때 표시합니다. 현재 폴더의 정렬 순서로 다음 TXT·PDF·압축파일·이미지 폴더를 찾으며, 마지막 항목이면 나가기만 표시합니다. 이미지 폴더 전체를 한 권으로 취급하고, 안내를 뒤로 닫으면 마지막 내용을 계속 볼 수 있습니다.
- 암호 압축·분할 압축·압축 속 압축은 지원하지 않습니다. 압축 방식에 따라 준비 시간이 필요하며 취소할 수 있습니다. 이미지 편집·OCR은 제공하지 않습니다.
- 원본 접근 권한이 유지되어야 다시 열 수 있습니다. 앱 캐시는 영구 오프라인 사본이 아닙니다.
- 강제 종료 직전 마지막 약 1초의 미저장 위치, 공급자 다운로드 지연, 아직 방문하지 않은 매우 긴 문단의 배치 시간은 제한으로 남습니다.

## 빌드와 검증

JDK 17, Android SDK 36, Build Tools 35.0.0이 필요합니다. `JAVA_HOME`과 `ANDROID_HOME`을 지정하거나 Android Studio에서 SDK를 설정합니다.

```sh
scripts/build.sh :core:txt:test :app:lintDebug :app:assembleDebug
scripts/create-signing.sh
scripts/build.sh :app:assembleRelease
```

Windows PowerShell에서는 다음 명령을 사용합니다. 개인 JDK·SDK 경로를 `.tools/env.ps1`에 두면 빌드 스크립트가 읽습니다.

```powershell
.\scripts\build.ps1 :core:txt:test :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
.\scripts\create-signing.ps1
.\scripts\build.ps1 :app:assembleRelease
```

산출물은 `app/build/outputs/apk/debug/app-debug.apk`와 `app/build/outputs/apk/release/app-release.apk`입니다. 서명 키와 비밀번호는 Git에 포함하지 않습니다. 같은 앱을 업데이트하려면 생성한 키를 보존해야 합니다.

다른 PC에서 새로 만든 키는 기존 APK의 서명과 다릅니다. 기존 설치를 업데이트하려면 원래 키와 `signing.properties`를 먼저 복원합니다. 키 없이 release를 빌드하면 설치할 수 없는 `app-release-unsigned.apk`가 생성됩니다.

전용 AVD의 E2E, 30분 연속 스크롤, 100회 재열기, 1/10/50/100MiB 부하, Macrobenchmark 명령은 [구현·실행 문서](docs/implementation.md)에 있습니다. 이번 배포 APK의 실제 화면·업데이트·실행 결과는 [0.2.0 검증 기록](docs/releases/0.2.0-verification.md), 이전 성능 측정은 [0.1.0 검증 기록](docs/releases/0.1.0-verification.md)을 확인해 주세요. 에뮬레이터 측정과 실물 기기의 성능 인수는 구분합니다.

PDF는 별도로 실제 이미지가 들어 있는 100MiB·300MiB 문서를 생성하여 확대·반전·스크롤·검색·재열기와 앱/렌더러 메모리를 검사합니다. [실행 방법](docs/implementation.md#대용량-pdf-부하-검사)과 [Android 11·16 검증 결과](docs/pdf-load-verification.md)를 참고해 주세요. 대용량 자료는 APK에 포함하지 않습니다.
